# 册子 #58 · 节点级目录与票选准入

**日期：** 2026-10-01
**直接上游：** `specs/2026-09-29-base-governance-circle-design.md`（`#33`：`govern.v1` 事件化与治理一致性）、`specs/2026-09-28-base-approval-governance-design.md`（`#27`：提案动作与门槛分档）、`specs/2026-09-28-base-contribution-roles-design.md`（`#23`：实时派生名册）、`specs/2026-09-29-base-course-category-design.md`（`#36`：分类契约）、`specs/2026-09-29-base-tagging-design.md`（`#37`：标签三元组）、`specs/2026-09-30-base-course-lesson-edit-design.md`（`#40`：`seq<0` 槽位）、`specs/2026-09-30-base-course-category-attr-design.md`（`#49`：`attr.category` 与双来源）
**范围：** 分类 / 讲师 / 标签三类**节点级目录**；个人新增词条的**票选准入**；**三态展示**（空 / 待票选 / 已通过）；分类**中文化**（撤掉 `attr.category` 的 slug 要求，改存词条键）。
**本册不覆盖：** 内容自身的审批闸门（沿用 `#51` 登记的「不建闸门」现状）；词条的改名 / 合并 / 删除治理；分类多级树与多归属；`#36` 导入器产 `category/<slug>` 的**形态**（本册只改它的**作用**）；真机验收执行。

## 1. 决策（已与用户逐条确认，执行时不要再翻案）

| # | 决策 |
| --- | --- |
| 1 | **名称即键**：词条键 = 规范化后的名称本身（可含中文），目录存「键 + 展示名」；`attr.category` / `attr.instructor` / 标签名存的就是这个词条键 |
| 2 | **准入门槛复用现行口径**：名册人数 < 10 时，创建者提交即 approved（小节点豁免，避免自己投自己）；≥ 10 时需名册内 2 票（与 `#27` 的 `edit` 同档） |
| 3 | **降级范围 = 全局一致**：未进目录的词条，**任何人（含创建者本人）**看到的都是「待票选」态，不存在「我看到、别人看不到」 |
| 4 | **一律显示「待票选」**：不再用「无分类 / 无讲师 / 无标签」覆盖已填词条（「无」只留给**字段本身未填**的情形） |
| 5 | **待票选名称要显示**：展示「原名称 + 灰色『待票选』角标」，票选通过后角标消失 |
| 6 | **单端点 + 本地缓存**：目录由 `GET /v1/directory` 一次下发（approved + pending），目录**不进内容包**、不触发 pack 重建；离线用最近一次缓存判三态 |

## 2. 数据模型

### 2.1 新表 `directory_terms`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `kind` | TEXT | `category` / `instructor` / `tag` |
| `term_key` | TEXT | 词条键（规范化后名称），主键之一 |
| `display_name` | TEXT | 展示名（首次提交时的原文，经清洗） |
| `state` | TEXT | `pending` / `approved` |
| `first_author_id` | TEXT | 首次提交者（可空，seed 行为空） |
| `created_at` / `updated_at` | TEXT | UTC |

主键 `(kind, term_key)`。**不新增 `items` 行、不进内容包、不进 `segments`**——目录是节点侧独立数据面。

### 2.2 `term_key` 规范化（定死，双端同构）

按序执行：

1. `TrimSpace`；
2. 全角 ASCII 可见字符 → 半角；
3. 连续空白折叠为单个半角空格；
4. ASCII 字母大小写折叠（**仅 ASCII**）；
5. 剥离控制字符（U+0000–U+001F、U+007F）；
6. 结果长度必须为 **1..64 rune**（与 `#37` 标签段同上限，故不窄于标签既有约束）。

**不做** Unicode NFC 归一化（与 `#38` 的标签收窄口径一致）。`display_name` = 规范化前的原文经步骤 2–5 清洗（保留大小写与全角，便于阅读）。

### 2.3 与既有契约的关系

- **分类**：`attr.category` 的取值语义由「分类 slug」改为「分类词条键」。`#36` 的 `category/<slug>` 容器条目**保留**（仍是分类的展示容器与组标题来源），但其**清单行不再承担归属**——归类只认 `attr.category` + 目录（`#49 §3` 的双来源收敛为单来源，见 §6）。
- **讲师**：`attr.instructor` 取值 = 讲师词条键。
- **标签**：`tag/<名称>/<章>/<节>` 的**名称段**即标签词条键（形态一字不改，中文本就可用）。
- **存量 seed**：首次上线时，把存量 `attr.category` 取值、`category/<slug>` 的 slug、存量 `attr.instructor` 取值、存量标签名称段**全部登记为 `approved`**（既成事实不追溯投票）。**漏掉这一步会让所有存量分类一夜之间变成「待票选」。**

## 3. 准入

### 3.1 复用提案通道，新增动作 `directory_add`

- 走既有 `POST /v1/proposal`，新增动作常量 `directory_add`，载荷 = `{kind, term_key, display_name}`（`kind` 必须 ∈ §2.1 三值；`term_key` 必须等于按 §2.2 规范化 `display_name` 的结果，否则拒）。
- **提案资格**：任何**已登记身份**（不要求名册内）——这是与 `#27` 现有动作的关键差异，否则新贡献者永远无法提案。
- 投票复用 `POST /v1/proposal/{id}/vote` 与既有 `govern_votes` 表；**票权 = 名册内**（`deriveRoster` 前 10）；提案人若在名册内则自计 1 票（沿用 `#27`），不在名册内则不自计。

### 3.2 门槛（F7 口径）

| 情形 | 结果 |
| --- | --- |
| `名册长度 < 10` | 提交即 `approved`（小节点豁免） |
| `名册长度 ≥ 10` | 需 **2 票**（含提案人自计，若其在名册内） |

门槛常量新增一个 `DirectoryAddQuorum = 2`，**不改** `#27` 既有的 `remove=3` / `edit`·`revive`=2。

### 3.3 同键归并

- 同一 `(kind, term_key)` 若已有 `pending` 提案，**不新建提案**，直接返回既有提案 id（幂等）；票数累加在同一提案上。
- 已 `approved` 的词条再次提交 ⇒ 直接返回成功，不建提案（幂等短路）。

### 3.4 通过的副作用

同一事务内：`directory_terms.state='approved'` + 写提案终态 + 投 `govern.v1` 事件（沿用 `#33`，**不新增签名域常量**），由 `eventsync` 跨节点同步。

## 4. 下发

### 4.1 `GET /v1/directory`（公开读）

```
{
  "version": 12,
  "approved": [ {"kind":"category","term_key":"数学","display_name":"数学"}, ... ],
  "pending":  [ {"kind":"category","term_key":"代数","display_name":"代数",
                 "votes":1, "threshold":2}, ... ]
}
```

- **公开读**（匿名可读），与 `GET /v1/contributors` / `GET /v1/proposal` 同类；内容全是词条名，无隐私面。路由隔离登记见 §6。
- `version` 单调递增，由目录任何变更（新增 / 通过）推进。
- 客户端携带本地 `version` 时，未变则返回 `{"version": n, "unchanged": true}`（响应体极小）；具体参数名见计划。

### 4.2 手机端缓存与离线

- 新增 `core/directory.ts`：`pullDirectory(opts)`（拉取并落缓存）、`loadDirectory(repo)`（读缓存）、`termState(kind, key)`（返回 `empty | pending | approved`）、`displayOf(kind, key)`。
- 缓存落本地 `config`：`directory_version` + `directory_terms_json`。
- 拉取时机：与内容同步同轮 + 进入课程页时（轻量，未变即不发数据）。
- **离线**：用最近一次缓存判三态；缓存缺失时**一律按 `pending`**（宁可显示「待票选」也不误显示为「已通过」）。

## 5. 三态展示

### 5.1 判定

| 态 | 条件 | 展示 |
| --- | --- | --- |
| `empty` | 字段本身未填 | 「无分类」/「无讲师」/「无标签」 |
| `pending` | 非空，且词条键不在 approved 集 | **原名称 + 灰色「待票选」角标** |
| `approved` | 词条键在 approved 集 | 名称，无角标 |

### 5.2 落点（全端同口径）

| 落点 | 位置 |
| --- | --- |
| 课程页分类分组头 | `apps/mobile/src/pages/course/course.vue` |
| 课程详情讲师行 / 课时详情讲师行 | `apps/mobile/src/pages/course/detail.vue`、`apps/mobile/src/pages/lesson/detail.vue` |
| 条目标签 chips | 文章 / 课程 / 课时 / 评论各页的标签展示处 |
| 「我创建的」区提示行 | `apps/mobile/src/pages/course/course.vue`（显示「分类待票选 · 已有 n/N 票」，**只加提示行，不改主展示**） |
| 节点门户 | `internal/httpapi/web.go` 的文章页与 `/governance` 看板 |

### 5.3 清洗与展示约束

- 展示名长度上限 **64 rune**（与 §2.2 同），UI 侧按容器宽度 CSS 截断。
- 剥离控制字符后再展示；`display_name` 为空 ⇒ 按 `empty` 态处理。
- **单条目待票选词最多显示 3 个**，超出折叠为「+n」。

## 7. 边界（本册明确不做）

1. 不做词条的**改名 / 合并 / 删除 / 退役**（`directory_add` 只增不改）；
2. 不做内容自身的审批闸门（沿用 `#51` 现状口径）；
3. 不做分类多级树与多归属；不做按标签检索与热度；
4. 不做 ② 类（加密）内容的词条关联；
5. 目录**不进内容包**、不新增 `items` 行、不改内容包规范 v1、不 bump `schema_version`；
6. 不做词条的**节点间合并冲突**处理（沿用 `govern.v1` 的 `(created_at, event_id)` 收敛口径，不做额外仲裁）；
7. 不做词条投票的截止时间与撤回；
8. 不做 iOS。

## 9. 风险

1. **存量 seed 遗漏** ⇒ 所有存量分类一夜之间变「待票选」。seed 必须是幂等迁移且**在目录端点开放前**完成。
2. **pending 展示名是用户自由文本**，会进全局展示面（含门户）⇒ 必须走 §2.2 清洗 + §5.3 条数上限；门户侧模板**必须保持转义**（不得因展示新字段而放松转义）。
3. **归一化过度合并**：全角→半角与空白折叠会把视觉上不同的写法并成一个键。这是「名称即键」的固有代价，登记为已知边界（反例记入册子，不做特判）。
4. **`attr.category` 取值语义变更**属契约级改动：老包（新版本手机端 + 老 app 版本）混用时会各自按自己的口径解释取值。缓解：seed 覆盖存量 slug，且新值域是旧值域的**超集**（旧 slug 仍合法）。
5. **目录端点是新公开面**，需接入既有公开读限速，避免被刷。
6. **提案资格放宽到非名册身份**，与 `#27` 现有动作的口径不同 ⇒ 必须在实现上按动作分档，不能顺手改 `#27` 的既有校验。
