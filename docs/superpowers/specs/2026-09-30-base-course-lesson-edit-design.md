## 0. 改版说明

### 0.1 2026-09-30 初版

**新增（本册子首次定义）：**

- **① 类二进制上传面 `POST /v1/blob`**（§3）：multipart 单块上传，返回 `blob_id`，与既有 `GET /v1/blob/{id}` 对称。这**破**既有缺口 G2「没有客户端 → 节点的 blob 上传入口」——但只服务 **① 类**（封面 / 附件）。
- **`segments` 的 `seq<0` 属性槽位**（§2.1）：`kind = attr.<key>`。`seq=0` 简介、`seq>=1` 子项清单两条既有约定**原样不变**。
- **课时新增 `attr.body_md`（Markdown 正文）** 与 **课时页（方案 A）**（§5.2）：课时页 = 正文 + 载体清单 + 附件 + 标签，**编辑入口只在这一页**。

- **载体类型登记 `audio`**（§2.4）：只落 kind 语义，**播放器与导入器 audio 支持另开册子**。
- **导入器遇投稿域容器跳过 + warning**（§4.3）：不静默改、不静默删。
- **三处重建路径保留 `seq<0` 行**的契约（§4.2）：`rebuildContainer` / `rebuildCategories` / `replaceTagLinksTx`。
- **课程页改版**（§5.1）：改纯课时清单，**下线**载体内联手风琴与「本课程测验（N 组）」汇总块。

**明确沿用、不改动：**

- 内容包规范 v1：`manifest.json` 字段名与类型、`pack.sqlite` 五表 DDL 与列顺序（总纲 §6.1 / §6.2）。**不新增表、不新增字段、不新增 `source` / `type` 枚举值、不 bump `schema_version`**。
- 两条哈希口径一字不改（#14 §3.3）：行级 `hex(sha256(UTF-8(text)))`、条目级 `hex(sha256(按 seq 升序拼接 "<kind>\t<text>\n"))`。
- `item_id` 路径式命名空间与「前缀即归属」（总纲 §6.0）。
- 可见性仍只有 `dist_class` 一维，**不引入新的权限维度**。
- 标签权威仍在节点侧 `tag_links`、不进包（#37）；课程分类仍由导入器产 `category/<slug>`（#36）。
- **② 类密文仍禁止借本上传面进节点**：`#9 §4.1` 的红线原样保留（② 类只能作为事件的一部分进入节点）。
- 老客户端（≤ `0.14.0`）在无改动下行为不变（§7）：`childrenOf` 只认 `seq>=1` ⇒ `attr.*` 行天然不可见。

### 0.2 2026-09-30 执行期更正

本册实施期（计划 `#41`）共 3 条与计划的偏差，均已在实现中收口：

1. **`attrsOf` 读取顺序由 `seq` 升序改为 `seq` 降序**：计划 Task 8 的 `attrsOf` 原稿按 `seq` **升序**读属性行，与 `assignAttrSeqs` 的产出顺序不自洽——后者按 `kind` 字典序从 `-1` 起**递减**分配，`attr.attachment` 多行时按 `blob_id` 升序占**递减** `seq`。若按升序读，多附件行的相对顺序会与写入口径相反。实现改为按 `seq` **降序**读。
2. **清掉页面稿未使用的 `DIFFICULTY_ADVANCED` import**：计划 Task 12 / Task 13 的页面稿 import 了未使用的 `DIFFICULTY_ADVANCED`，执行期已移除（`tsc --noEmit` 干净）。
3. **`AttrSeqsCanonical` 判据改为与入参数组顺序无关**（0.15.0 实测缺陷）：计划 Task 2 的原稿逐元素比对，隐含要求调用方按 `AssignAttrSeqs` 的产出顺序（`seq` **降序**）传入；而 `validateSubmitSegments` 为查重先按 `seq` **升序**排过，于是 **≥2 条属性行必判 `item_segments_invalid`(400)**——0/1 条属性行时顺序退化同序，故 D1–D7 全绿而线上失败。实现改为两侧都按 `seq` 升序对齐后逐行比对；判据强度不降（`seq` 取值、attachment 的连续递减区间、同 kind 内 text 升序仍须逐字节吻合）。测试缺口同时补上：`validateSubmitSegments` 的 ≥2 属性行路径此前无任何用例覆盖。

## 1. 范围与不做什么

**做五件事：**

1. **字段模型**：课程 / 课时的全部字段落在 `segments` 的固定槽位上（§2.1），零新表零新字段。
2. **上传面**：新开 ① 类二进制上传 `POST /v1/blob`（§3）。
3. **写路径**：投稿解锁 `course` / `lesson` 两个容器形态，服务端按容器口径算 `content_hash`（§4.1）。
4. **双端编辑**：手机端课程 / 课时编辑页（新建 + 编辑同页两模式），正文用 Markdown 源文本编辑（§6）。
5. **展示**：课时页（方案 A）新增 + 课程页改纯清单（§5）。

**明确不做：**

- **不做按标签检索内容**（另开册子，归展示侧）。
- **不做 audio 的播放器与导入器支持**（另开册子）；本册只登记 `audio` 的 kind 语义。
- **不做节点侧课程 / 课时管理接口**：不设 `POST /v1/course`、不设增删改专用路由；课程与课时的**编排**走导入器（本地产出）或投稿（`POST /v1/submit`）两条既有面。
- **不做课程分章 / 分单元、不做课时分页**：课时清单就是一条纵向列表。
- **不做富文本 HTML 编辑器**：正文即 Markdown 源（与 `articles.body_md` 同口径），不引入第三方编辑器库。
- **不做课程 / 课时的删除**：下架与改写归 #27 提案（`remove` / `edit`）。
- **不做学习进度**（归 #8）、**不做读取鉴权**、**不做 iOS**。
- **不改 `tools/migrate`**：Strapi 迁移路径保持现状。

## 2. 契约边界

### 2.1 槽位表（本册的字段模型）

全部字段落在 `segments` 的固定槽位，**零新表零新字段**：

| 槽位 | `kind` | `seq` | 承载 | `text` 形状 |
|---|---|---|---|---|
| 简介 | `digest` | `0` | course / lesson | 纯文本（既有） |
| 子项清单 | 子项自身的 kind | `1..n` | course → `lesson`；lesson → `article\|video\|audio\|quiz` | 子项 `item_id`（既有） |
| 封面 | `attr.cover` | `<0` | course / lesson | `blob_id` |
| 讲师 | `attr.instructor` | `<0` | course / lesson | 纯文本 |
| 难度 | `attr.difficulty` | `<0` | course / lesson | 枚举 `intro` / `basic` / `advanced` |
| 时长 | `attr.duration` | `<0` | course / lesson | 秒数（十进制字符串） |
| 附件 | `attr.attachment` | `<0` 连续区间 | course / lesson | `<blob_id>\t<文件名>` |
| 课时正文 | `attr.body_md` | `<0` | lesson | Markdown 源 |

铁律：

1. **三区间不混**：`seq<0` 只放属性行（`kind` 必以 `attr.` 开头）；`seq=0` 只放简介；`seq>=1` 只放子项清单。
2. **`seq<0` 的分配规则写死**（确定性导出的前提）：`attr.*` 按 `kind` **字典序从 `-1` 起递减**分配；同一 `kind` 至多一行，唯 `attr.attachment` 可多行——**多行占连续递减区间**，同一 `kind` 内按 `blob_id` 升序映射到递减 `seq`。
   例（六种属性全给）：`attr.attachment`×2 → `-1,-2`；`attr.body_md` → `-3`；`attr.cover` → `-4`；`attr.difficulty` → `-5`；`attr.duration` → `-6`；`attr.instructor` → `-7`。
3. **属性行不参与子项解析**：`childrenOf` / `childIDsOf` 继续只认 `seq>=1`，`digestTextOf` 继续只认 `seq=0`——三者的既有语义一字不改。
4. **未设置的可选属性不写行**：不写空行。否则同一字段集在编辑一次后会算出不同 `content_hash`。
5. 标题走 `items.title`（既有），**不进 `segments`**。
6. 分类、课时序号、标签**一律不落字段**：分类仍由导入器产 `category/<slug>`（#36）；课时序号 = 清单位次（#14 §6）；标签走 `tag_links`（#37）。

### 2.2 课时不新写简介行

- 新写路径（投稿 / 编辑面）**不产** `kind=digest` 的课时行；课时摘要 = **正文首段截断**（客户端派生）。
- 既有导入器产出的课时 `digest` 行**保留可读**（老包与 「#14 §4.2 规则 4」不变），客户端读摘要时**优先 `seq=0`、缺失才回落正文首段截断**。
- 理由：同一信息两个权威必然漂移；摘要无独立语义，不值得多一版真值。

> 与 #14 §3.1 的关系：该条「lesson 承载 `kind=digest, seq=0` 的课时简介」**不废止**（导入器照旧产出、客户端照旧可读），本册只是**不给它写路径**。口径回填见 §11 的 #14 §0.4。

### 2.3 投稿解锁两个容器形态

- `POST /v1/submit` 新增接受 `type=course`（`item_id = course/<cid>`）与 `type=lesson`（`item_id = course/<cid>/lesson/<lid>`），`source` 同形（`course` / `lesson`）。
- `content_hash` 口径 = **容器口径**（#14 §3.3 条目级：按 `seq` 升序拼 `"<kind>\t<text>\n"`），**服务端算、客户端不传**（与 #25 一致）。该口径与 #37 §3.4 的 `tag` 容器口径同源。
- 其余前缀的拒绝口径不变：`course/` 前缀不再一律拒，但**非容器形态**（如 `course/<cid>/lesson/<lid>/article/<aid>` 类型标成 `course`）仍拒，错误码沿用 `item_id_invalid` / `item_type_mismatch`（#25 §2.4）。
- **占用口径完全沿用 #25**：同 `item_id` 已存在且 `items.author_id` 为空（导入器域存量条目）⇒ 拒绝；`author_id` 非空 ⇒ 仅本人可改写（改写必重签）。
- **写路径只覆盖投稿自建容器**：导入器域的课程 / 课时**只读**（其改写归 #27 提案线，不在本册）。

### 2.4 载体类型与 `audio`

- 课时清单的子项 `kind` 取值集合扩为 **`article` / `video` / `audio` / `quiz`**。
- `audio` 条目落**既有 `media_meta` 表**（复用 `blobs` 与分块路径），**靠 `mime` 前缀 `audio/` 区分**——不新增表、不新增字段、不新增 `source` / `type` 枚举值（`source=lesson` + `type=audio`）。
- 本册**只登记 kind 语义**：清单里 `kind=audio` 合法、`media_meta.mime` 以 `audio/` 开头即 audio 载体。**播放器、导入器 audio 支持、`tagKindRank` 的 kind 集合调整均不在本册**（已知边界见 §8）。
- 老客户端遇 `audio`：走 `openCarrier` 末句「暂不支持的类型」toast ⇒ **降级安全**（不白屏、不崩、不误开）。

## 3. 上传面：`POST /v1/blob`（① 类二进制）

| 项 | 约定 |
|---|---|
| 形态 | `multipart/form-data`，**单块**，字段名 `file` |
| 服务端 | 读字节 → 算 `blob_id = hex(sha256(字节))[0:32]`（既有 `protocol.BlobID`）→ 落块 → 返回 `{"blob_id": "..."}` |
| 幂等 | 同字节重复上传返回**同一** `blob_id`（内容寻址天然去重），不重复落盘 |
| 资格 | 持有效签名头的身份，**沿用 S1 `authenticate` 中间件**；不新增权限维度、不新增配置项 |
| 限速 | 沿用既有写接口限速（与 `POST /v1/submit` 同口径） |
| 上限 | 单请求 **8 MiB**；超限返回 `413` + `blob_too_large` |
| 错误码 | `blob_too_large`（413）· `bad_multipart`（400）· 既有签名类（401） |
| 落盘 | 与 `GET /v1/blob/{id}` 同一目录、同一算法，读回字节逐字节一致 |
| **禁用面** | **只服务 ① 类（封面 / 附件）**；② 类密文仍必须借事件进节点（`#9 §4.1` 红线保留） |
| 不做 | 不做逐块鉴权（与总纲 §12 第 15 条「块保持匿名可取」同向）；不做分片与断点续传 |

> 上限 8 MiB 的取值理由：封面与附件的典型尺寸。**音频载体的上传能力不在本册**（另开册子），故此处不按音频尺寸定档。

## 4. 写路径与落库

### 4.1 容器条目的写路径

1. 客户端编辑页产出**完整 `segments` 行集**（含 `seq<0` 的 `attr.*` 行与 `seq>=1` 的清单行）。
2. 经 `POST /v1/submit` 提交（`type=course|lesson`），**服务端算 `content_hash`**（§2.3）。
3. 服务端落库走**既有 `store.UpsertSegmentItem`**（`items` + `segments` 同事务，先删同 `item_id` 旧行再按 `seq` 升序写入）——因此**调用方必须把既有 `seq<0` 行原样带入**（§4.2）。
4. **允许空容器**：课程暂无课时、课时暂无载体时，清单为空，只有 `attr.*` 行（与可选的 `digest` 行）。
5. 封面 / 附件先走 `POST /v1/blob` 拿 `blob_id`，再写对应属性行。

### 4.2 保留 `seq<0` 行的契约（三处重建路径）

| 位置 | 现状 | 本册契约 |
|---|---|---|
| `internal/importer/course.go` `rebuildContainer` | 读既有 → `mergeChildren(childIDsOf(existing), children)` 重建；`digest` 只取 `seq=0` | **必须把既有 `seq<0` 行原样并入重建结果**（否则导入器一跑就抹掉投稿方写的封面 / 讲师 / 正文） |
| `internal/importer/course.go` `rebuildCategories` | 全量快照重写（刻意不 merge 子项）；`digest` 只取 `seq=0` | 同上：保留既有 `seq<0` 行 |
| `internal/store/tag.go` `replaceTagLinksTx` | `DELETE FROM segments WHERE item_id=?` 后重写物化行 | 改为只删 `seq>=1` 行，**保留 `seq<0` 行** |

- `UpsertSegmentItem` 本身**不改**（它是低层原语，「先删后写」的语义由调用方保证传入完整行集）。
- 三处均**不改** `childrenOf` / `childIDsOf` / `digestTextOf` / `MaterializeTagSegments` 的既有语义。

> `replaceTagLinksTx` 这条改动在**今天是防御性**的（标签条目当前不产 `seq<0` 行）。写进契约的目的不是修 bug，而是让「哪些重建路径会抹掉属性行」有唯一答案——避免以后逐个 case 现判。

### 4.3 导入器遇投稿域容器：跳过 + warning

- **判据**：该容器在库中已存在且 `items.author_id` 非空（即投稿域）。
- **行为**：跳过该容器的重建——不改 `items`、不改 `segments`、不 `RetireItem`；汇总一条 warning 到 Run 结果（形如 `skipped: course/<cid> 投稿域，导入器不覆盖`）。
- **不静默改、不静默删、不阻断整批导入**（与 #14 §4.2 规则 6 的「失败明细不整批失败」同口径）。

## 5. 展示形态

### 5.1 课程页（改版）

- **数据结构**：课时清单 = `childrenOf(course)` 的顺序（`seq>=1` 升序），第 N 项即「第 N 讲」（与 `lessonNo` 同一算法）。
- **每行三段**：`第 N 讲 · 标题` + 类型徽标（`article` / `video` / `audio` / `quiz` 各自计数；附件数；时长）+ 标签 chips。
- **点整行 → 进课时页**。**下线**载体内联手风琴展开（原「单载体直开 / 多载体展开」两级跳转退场）。
- **下线**底部「本课程测验（N 组）」汇总块：quiz 已在课时页载体清单里，同一份数据不再有第二个渲染面。
- **空课时不隐藏**（标「空课时」）：隐藏会让后续序号整体前移，与 `lessonNo` 位次错位。
- **悬空引用占位不跳过**（清单指向本地不存在的课时，标题退化为 `item_id`）：同样为保住位次。
- 课程级字段在页顶展示：封面、简介（`seq=0`）、讲师、难度、时长、附件、标签。
- 课时多时**不分页、不分章**，纵向清单直滚。

### 5.2 课时页（方案 A，新增页）

```
标题（含「第 N 讲」）
 ├─ 正文        attr.body_md（Markdown 渲染）
 ├─ 载体清单    childrenOf(lesson)，点进 article / quiz / video / audio 页
 ├─ 附件        attr.attachment（blob 下载 / 打开）
 └─ 标签 chips
```

- **编辑入口只在这一页**（可见性见 §6）。
- 正文缺失（老包无 `attr.body_md`）：只显示载体清单，**不显示空正文块**。
- 空载体：显示空态，不报错（与 §4.1 第 4 条呼应）。
- 课程页**不展示**课时正文，也**不展示**课时摘要（手风琴已下线，见 §5.1）——摘要口径（§2.2）只服务于课时页自身与后续册子。

## 6. 编辑面（手机端）

- **两页**：课程编辑页、课时编辑页（同一套表单形态）。入口：课程页（课程）、课时页（课时）。
- **新建 + 编辑同页两模式**：
  - 新建：客户端按既有 `protocol.ValidSlug` 规则（`[a-z0-9][a-z0-9-]{0,63}`）生成 slug → `course/<slug>` / `course/<cid>/lesson/<slug>`。
  - 编辑：读既有条目 → 回填表单 → 提交完整行集。
- **正文编辑 = Markdown 源文本**（多行），与 `articles.body_md` 同口径；**不引入第三方富文本 / HTML 编辑器**。
- **封面 / 附件**：先 `POST /v1/blob` 拿 `blob_id`，再写 `attr.cover` / `attr.attachment` 行。
- **落库**走 §4.1；**离线入队复用既有 `my_submissions` 台账**（#29）——**零新表**。
- **编辑入口可见条件**：容器 `items.author_id` == 本人。导入器域容器（`author_id` 为空）与无权改写的容器**只读**，改动走 #27 提案（§2.3）。

## 8. 已知边界（登记，不在本册修）

1. **`tagKindRank` 未含 `audio`**：`internal/store/tag.go` 的 kind 固定序是 `course|lesson|article|comment`。若将来给 audio 载体打标，该 kind 会落 rank `4`（与 `comment` 同档、混序）。本册标签面**不覆盖 audio 载体**，故**登记不改**；audio 册子必须一并处理。
2. **属性行对条目哈希是位置敏感的**：`seq<0` 的分配规则（§2.1 铁律 2）必须**双端逐字节一致**，否则同一字段集在两端算出不同 `content_hash`，重复投稿会被当作新版本。本册把规则写死为契约，并在 AC 1 加契约向量守。
3. **`POST /v1/blob` 的 8 MiB 只覆盖封面 / 附件**：音频载体上传能力不在本册。
4. **课程页信息密度下降**：不再内联载体清单 ⇒ 到载体多一步点击（明确取舍，换课时页的正文 / 附件 / 标签承载）。
5. **双写同一容器的隔离只靠「投稿域跳过 + warning」**：导入器不校验投稿域容器的字段合法性（那是写路径的责任），仅跳过。

## 12. 风险点

1. **新增写面即新增攻击面**：上传面可被用来填满节点磁盘，**上限 + 限速是唯一护栏**；容量上限与 LRU 淘汰仍未做（总纲 §12 第 6 条），本册不解决。
2. **属性行位置敏感**：任何一端改了 `seq<0` 的分配顺序，双端 `content_hash` 立刻漂移且**不会报错**（会被当成新版本静默入库）。AC 1 的契约向量是唯一守门。
3. **导入器与投稿双写同一容器**：靠 §4.3 的「跳过 + warning」隔离；warning **不阻断**整批导入，故运营需看 Run 输出。
4. **课时页成为唯一内容入口**：课程页到载体多一步，且课程页不再能一眼看到载体分布（只有徽标计数）。
