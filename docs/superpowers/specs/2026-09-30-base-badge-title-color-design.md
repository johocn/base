## 2. 契约

### 2.1 槽位定义

两个新 kind 落在 `#40 §2.1` 的 `seq<0` 属性行机制内，**零新表零新字段**：

| 槽位 | `kind` | `seq` | 承载 | `text` 形状 |
|---|---|---|---|---|
| 图章 | `attr.badge` | `<0` | course / lesson | 中文词，**多值**用半角逗号 `,` 连接（去重 + 码位升序）；可选，空则不产该行 |
| 标题高亮 | `attr.title_color` | `<0` | course / lesson | 单值枚举：`red` / `orange` / `green` / `blue` / `purple` / `gray`；可选，空则不产该行 |

- **同一 kind 至多一行**：`attr.badge` **多值落单行**（不是多行）；`attr.title_color` **单值单行**。二者都**不**走 `attr.attachment` 那种「多行占连续递减区间」的例外（铁律 2 的例外只属于 `attr.attachment`）。
- **未设置不写行**（`#40 §2.1` 铁律 4）：`attr.badge` / `attr.title_color` 为空时不产该行，否则同一字段集编辑一次后会算出不同 `content_hash`。
- **三处同步**：常量与 `AttrKindSet` 必须同时在
  - `internal/protocol/attrs.go`（常量块 L6-23 + `AttrKindSet` L26-33）
  - `apps/mobile/src/core/attrs.ts`（镜像常量 L12-29 + `ATTR_KIND_SET` L31-38）
  - `vectors/v1/attrs.json`（新增用例）
  
  任一端漏改，`AssignAttrSeqs` 的 `seq<0` 排布会在两端漂移，进 `content_hash` 后**静默出新版本而不报错**（`#40 §8 风险 2`）。

### 2.2 `attr.badge` 取值域与身份分档

取值域**封闭**（7 个中文词，均为 2 字词，**不含**分隔符 `,`）：

| 词 | 作者（编辑自建条目） | 治理者（`#23` 名册内） |
|---|---|---|
| `活动` | ✅ | ✅ |
| `悬赏` | ✅ | ✅ |
| `辩论` | ✅ | ✅ |
| `置顶` | ✅ | ✅ |
| `热门` | ❌ | ✅ |
| `精华` | ❌ | ✅ |
| `推荐` | ❌ | ✅ |

- **作者**编辑**自建**条目时可选 **4 种**：`活动` / `悬赏` / `辩论` / `置顶`（`置顶` **仅限自己**——即只用于自己创建的条目）。
- **治理者**编辑时可选 **7 种**：`热门` / `活动` / `悬赏` / `精华` / `推荐` / `置顶` / `辩论`。
- 身份判定沿用既有两处**不加新维度**：作者身份 = 「该条目 `author_id` == 本人」（编辑入口的既有可见条件，`#40 §6`）；治理者身份 = `#23` 实时派生的本节点贡献前 10 名名册（`GET /v1/contributors` 同一口径）。
- **服务端不因中文词做身份分档拦截**：`AttrKindSet` 只认 kind 合法（`attr.badge` 是合法属性行），**取值域白名单由客户端与服务端共用的一份纯函数校验**（§2.3），身份分档是**编辑端 UI 的可选项集合**。越权增选（作者选 `热门`）属**客户端拦截**；本册不为取值域新增服务端错误码（保持零新枚举、零新错误码）。
- **不做自定义文本**：`attr.badge` 的 `text` 只由上述取值域内的词连接而成，**不接受自由文本**（拒绝任意字符串进入图章，避免成为第二套标签体系）。

### 2.3 序列化与排序规则（`attr.badge`）

- **分隔符**：**半角逗号 `,`**。理由：取值域全部是中文词，**不含逗号**，故 `,` 无歧义；且半角逗号在最窄的字符面上也可安全裁剪。
- **归一化（写前）**：① 去重（重复词只留一个）；② 按**码位升序**（Unicode code point 升序 / UTF-8 字节序）排列；③ 用 `,` 连接成**单行** `text`。
- **规范序（7 词全给时的定序）**：`活动` < `悬赏` < `推荐` < `热门` < `精华` < `置顶` < `辩论`（按首字码位升序；写入口径与读入口径必须一致，否则同一字段集两端算出不同 `content_hash`）。
- **读入（解析）**：按 `,` 切分 → 去空项 → **再次去重 + 码位升序**（对不会规范形态容忍）→ 只保留取值域内的词，域外词**静默丢弃**（坏一行不阻塞条目展示，与 `attrsOf` 的既有「未知 kind / 坏行静默忽略」同口径）。
- **纯函数**：`serializeBadge(words: string[]): string` 与 `parseBadge(text: string): string[]`（TS；Go 侧若需要同口径校验亦为纯函数），**无异常分支、单出口**，是双端共享向量（`vectors/v1/attrs.json`）覆盖的对象。
- **`attr.title_color` 归一化**：写前校验 `name ∈ {red,orange,green,blue,purple,gray}`，域外值**不产该行**（宁可无色，也不落一个非法色名）。

### 2.4 标题高亮与色名（`attr.title_color`）

- **独立槽位**：`attr.title_color` **不是** `attr.badge` 的一部分——图章与标题色可各自独立存在、互不影响。
- **色名枚举复用例 `#44 §6` 的 6 个字色**：`red` / `orange` / `green` / `blue` / `purple` / `gray`；**不含** `c-mark`（高亮底是背景色，标题高亮只改字色，避免与 6 字色冲突，与 `#44 §6` 的「`c-mark` 只给背景、不覆盖字色」约束同向）。
- **标题仍是纯文本**：`title_color` 只决定「给标题套哪个色类」，**标题文本不解析、不渲染**——**不走** `#44` 的 `renderMarkdown`，不进 `#44 §3` 的消毒白名单。
- **不经过消毒的理由**：`title_color` 只产出一个**从 6 名白名单里选出的固定类名**（`c-red` … `c-gray`），不含任何用户可控字符——类名本身即白名单常量，**不存在注入面**，故无需进消毒管线。若将来允许标题富文本则必须回到 `#44 §3` 白名单，本册明确不做（见 §1）。
- **展示类名**：显示时给标题元素套 `c-<name>`（与 `#44 §6` **同名色板**），故三端各自样式表只需保证 `c-<name>` 对标题元素生效（§2.5）。

### 2.5 展示落点

**图章与标题高亮落点相同**：均显示在**条目标题旁**（列表页与详情页）。

| 端 | 落点 | 图章 | 标题高亮 |
|---|---|---|---|
| App 列表 | `pages/course/course.vue` 的课程行标题旁 | 标题旁 chips | 标题套 `c-<name>` |
| App 详情 | `pages/lesson/detail.vue` 的 `lessonLabel` 标题旁 | 标题旁 chips | 标题套 `c-<name>` |
| App 阅读 | `pages/article/article.vue`（`#44 §5` 同落点） | 标题旁 chips | 标题套 `c-<name>` |
| 节点门户 | `internal/httpapi/web.go` 的 `pageData` / `handleArticlePage` + `web/templates/article.html` | 标题旁 chips | 标题套 `c-<name>` |

- **与 `#44 §5` 三端落点一致**（App 阅读两页 + App 编辑预览面 + 节点门户的同源改造）；本册只在**已由 F5 改好的页面结构**上挂展示，**不重构页面结构**。
- **列表页与详情页同落点**：图章 chips 与标题色类在列表与详情两处都出现（`course.vue` 列表行 + `lesson/detail.vue` 详情标题）。
- **门户**：`article.html` 的 `<h1>{{.Title}}</h1>` 旁追加图章；标题类名按 `c-<name>` 套在 `<h1>` 上；门户**只有一套浅色主题**，故只落浅色一版色值（与 `#44 §5.3` 同）。

### 2.6 写入通道

- **复用既有 `POST /v1/submit` 的条目编辑路径**（`#40 §4.1` / `#41`）：作者改自己的条目，图章与标题色**随条目一起提交**（在 `segments` 行集里作为属性行），**零新接口**。
- **编辑编排**：复用既有 `ContainerForm`（`apps/mobile/src/core/course-edit.ts:48-66`）——新增 `badge` / `titleColor` 两个表单字段；`buildContainerSegments`（`course-edit.ts:99-114`）在 `assignAttrSeqs` 之前把两行 push 进 `lines`；`loadContainerForm`（`course-edit.ts:117-132`）经 `attrsOf` 回填。
- **读取视图**：`ContainerAttrs` / `emptyAttrs` / `attrsOf`（`apps/mobile/src/core/container-view.ts:24-79`）新增 `badge: string[]`（解析后的数组）与 `titleColor: string` 两个字段；`attrsOf` 对两个新 kind 加分支，未知 / 坏值静默忽略（保持既有容错口径）。

### 2.7 老条目兼容与字典序落点（**必读**）

新增两个 kind 后，`AssignAttrSeqs`（`attrs.go:58-88`）**只对入参里实际出现的 kind 排序**，故：

- **字典序落点（核实结论）**：
  - `attr.badge` 落在 **`attr.attachment` 与 `attr.body_md` 之间**（`attr.a` < `attr.b`，且 `attr.ba` < `attr.bo`）。
  - `attr.title_color` 落在 **`attr.instructor` 之后**（`attr.i` < `attr.t`），是当前 8 个 kind 里的**最末**。
  - 8 个 kind 的完整名次：`attr.attachment` → `attr.badge` → `attr.body_md` → `attr.cover` → `attr.difficulty` → `attr.duration` → `attr.instructor` → `attr.title_color`（`#49` 的 `attr.category` 落在 `attr.body_md` 与 `attr.cover` 之间）。
- **不含这两行的老条目**：`AssignAttrSeqs` 的排布与既有**逐字节一致**，`AttrSeqsCanonical` 仍通过，**不产生新版本**（AC 4）。
- **含 `attr.badge` 的条目**：因 `attr.badge` 名次靠前（除 `attr.attachment` 外所有既有 kind 之前），**其后所有既有属性行的 seq 整体下移**——排布与旧版本不同。
- **含 `attr.title_color` 的条目**：它名次**最末**，只**追加**一条最低 seq，**既有属性行 seq 不变**，但排布整体仍与旧版本不同（多一行）。
- **共同必然结果**：**任一被加上这两个新行之一的条目，其 `content_hash` 变化 ⇒ 产生新版本**。这是「**给老条目加图章 = 产生新版本**」的必然结果，与「**老条目无该行 ⇒ 排布不变**」是**两件事**，不得混为一谈：
  - 「无该行」讲的是**未编辑的老条目**（不产行、不重算哈希、不产生新版本）；
  - 「加图章」讲的是**被编辑并新增了行的条目**（必然重算哈希、必然产生新版本——这是既有的「改写必重签 / 新版本」机制，非本册新引入）。

## 3. 已知边界（登记，不在本册修）

1. **给他人条目打图章不在本册**：语义上归 `#27` 的 `edit` 提案（2 票）路径，但本册**不扩 `#27` 的载体范围**（`#27 §0.3` / `§0.5`：`edit` 载体仍只有 `articles` 型与 `tag` 型，且 `edit` 载荷是 `title` + `body_md` / `links[]`，**没有图章槽位**）。要在他人条目上打图章，需另开册子定义 `edit` 载荷扩图章 —— **本册登记不改**。
2. **文章条目不承载图章 / 标题色**：两个新 kind 是 `segments` 的 `seq<0` 属性行，载体是 course / lesson；文章（`articles` 表）**不产 `segments` 行**。故 `article.vue` 与门户 `handleArticlePage` 只作为「与 `#44 §5` 相同的落点」登记，文章页的图章 / 标题色在无载体行时**自然为空**。若要给文章打图章，需另开册子为文章定义属性载体（涉及新槽位或新表）。
3. **服务端不做身份分档拦截**：作者越权增选（选 `热门`）由**编辑端 UI 可选项集合**拦截；本册不为取值域新增服务端错误码（零新枚举、零新错误码）。若需服务端强拦截，需另开册子新增校验与错误码。
4. **图章热度与排序不做**：不统计图章出现次数、不做「热门」自动计算、不做按图章排序 / 筛选。`热门` 只是一个**手动可选词**，与统计无关。
5. **标题不进渲染管线**：标题恒为纯文本，只套色类；标题内联语法（`**粗**` / `[文字]{.c-red}`）**不生效**（与 `#44` 只覆盖 `attr.body_md` 一致）。

## 7. 风险点

1. **双端漂移（最大成本项）**：`attr.*` 的 `seq<0` 排布进 `content_hash`，Go 与 TS 任一端漏改 `AttrKindSet` 或排序规则，同一字段集两端算出不同哈希且**不会报错**（`#40 §8 风险 2`）。压舱石是 `vectors/v1/attrs.json`（AC 1 / AC 3 / AC 4）。
2. **「加图章 = 产生新版本」被误读**：加图章会重算 `content_hash` 并产生新版本，这是**必然结果**，须与「老条目无该行 ⇒ 排布不变」严格区分（§2.7），否则会被当成缺陷。
3. **取值域与分隔符的一致性**：`attr.badge` 的中文词排序若两端实现不同（如按 `localeCompare` 而非码位），会静默漂移。规则定死为**码位 / UTF-8 字节序**（与 kind 排序同口径，`sort.Strings` 等价），由共享向量守。
4. **载体边界被误解**：图章 / 标题色的载体是 course / lesson（`segments`），文章条目不承载（§3 第 2 条）。若验收时拿文章页找图章会落空——须以 §2.5 的载体说明为准。
5. **图章被当第二套标签**：取值域封闭 + 不做自定义文本（§2.2）+ 不进 `#37` 标签体系（§2.5），是防止图章退化为标签体系的护栏；实施时**不得**放开自定义文本。
