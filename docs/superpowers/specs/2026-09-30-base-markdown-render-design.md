## 0. 改版说明

### 0.1 2026-09-30 初版

**新增（本册子首次定义）：**

- **正文渲染管线**（§2 / §4）：`attr.body_md` 一份源文本 → 「解析 → 消毒 → HTML」，三端（App 阅读 / App 编辑预览 / 节点门户）共用同一套语法与消毒规则。这**破的是既有实现口径**（`internal/httpapi/web.go` 的「P0 不做 Markdown 渲染，原样纯文本展示」与两端的 `split('\n\n')`，已在 `#40 §0.2` 第 4 条登记），**不破任何册子契约**：`#40` 本身只标注了「正文 Markdown 渲染」而未定义机制，故本册是**补定义**。总纲 §0.10 已同步补定义。
- **变色扩展语法**（§2.2）：`[文字]{.c-red}` → `<span class="c-red">文字</span>`，高亮底 `[文字]{.c-mark}`。与 Markdown 链接 `[文字](url)` 的歧义按「后缀定归属」消解。
- **消毒白名单**（§3）：标签白名单 + 属性白名单 + `span.class` 枚举 + `href/src` 协议白名单。**渲染函数是唯一出口**，三端不得旁路。
- **双端一致性靠共享契约向量**（§4）：Go test 与 vitest 读**同一份 JSON 用例表**（`md → 期望 HTML`），任一端漂移立即红。
- **色板**（§6）：6 字色 `c-red` / `c-orange` / `c-green` / `c-blue` / `c-purple` / `c-gray` + 1 高亮底 `c-mark`，浅色 / 护眼 / 暗色各配一版，靠 CSS 变量跟随主题，**不需要重渲染**。
- **编辑端工具栏 + 实时预览**（§5.2）：现有裸 `<textarea>` 之上加语法工具栏（插入语法，变色按钮带选色弹层并包裹选区）与编辑区下方实时预览。
- **节点门户改直出**（§5.3）：`splitParagraphs` → `renderBody()`，模板由 `{{range .Paragraphs}}<p>{{.}}</p>{{end}}` 改为 `{{.Body}}`，**必须显式关转义**（`template.HTML`）——故消毒是门户侧的前置条件，不是可选项。

**明确沿用、不改动：**

- 内容包规范 v1：**不新增表、不新增字段、不新增 `source` / `type` 枚举值、不 bump `schema_version`**。渲染是**只读派生**，结果不落库、不入包。
- `attr.body_md` 槽位语义与 `#40 §2.1` 槽位表一字不改（仍是 Markdown 源文本）。
- `item_id` 路径式命名空间与「前缀即归属」（总纲 §6.0）。
- 可见性仍只有 `dist_class` 一维，**不引入新的权限维度**。
- 两条哈希口径一字不改（#14 §3.3）：正文变成 HTML 渲染**不影响** `hex(sha256(UTF-8(text)))`——哈希吃的是源文本。
- 答案 / 题目 / 评论正文**不在本册范围**：本册只改 `attr.body_md`。`articles.body_md` 与 `attr.body_md` 同口径，故 `article.vue` 一并纳入（§5.1）。

## 2. 语法契约

### 2.1 支持的子集

| 语法 | 产出 | 备注 |
|---|---|---|
| `# ` ~ `### ` | `h1`~`h3` | 四级及以上降级为 `h3` 文本，**不产出 `h4`** |
| `**粗**` / `*斜*` | `strong` / `em` | 支持嵌套 |
| `` `代码` `` | `code` | 行内 |
| `- ` / `1. ` | `ul` / `ol` + `li` | 支持一层嵌套缩进（两空格） |
| `> ` | `blockquote` | 连续行合并为一个块 |
| `---` | `hr` | 独占一行的三个及以上连字符 |
| `[文字](url)` | `a[href]` | `url` 只允许 `http(s)://`；非白名单协议与相对路径按 **§3「丢弃该属性」**处理——保留文本、丢 `href`（`[x](javascript:alert(1))` ⇒ `<a>x</a>`），**不是**整段原样输出 |
| `![alt](url)` | `img[src,alt]` | `url` 只允许 `http(s)://`，非白名单同理**只丢 `src`**（`![x](javascript:alert(1))` ⇒ `<img alt="x">`）；**无图床，只支持外链**（§8） |
| 空行 | 段落切分 | 与现状同口径 |
| 单换行 | 段内换行 | 产出 `br` |

### 2.2 变色扩展与歧义消解

- 语法：`[文字]{.c-x}`，`x ∈ {red, orange, green, blue, purple, gray, mark}`。
- 产出：`<span class="c-x">文字</span>`。`文字` 允许行内语法（`**粗**` 等）嵌套。
- **歧义消解（硬规则）**：`[A](B)` 归链接、`[A]{.c-x}` 归变色、两者都不匹配则 `[` `]` 原样输出。解析顺序为「先试变色后缀 `]{.c-`，再试链接后缀 `](`」。
- **未知类名**：`[文字]{.c-foo}` 中 `foo` 不在枚举内 ⇒ **整段按字面量原样输出**（不产出 `span`），不静默降级为无色。
- **转义**：`\[` 输出字面量 `[`；`\]` 同。转义优先于上述所有规则。

### 2.3 降级总则

任何**未匹配**的语法标记一律按字面量原样输出，**不吞字符、不抛错**。解析器对任意输入必须返回结果（不含异常分支），这条是共享向量的固定用例之一。

**裸 HTML 不是语法**（§1 明确不做 HTML 内嵌）：`<script>x</script>`、`<img src=x onerror=alert(1)>` 这类输入一律当**普通文本**处理，只做 §3 的文本转义（`&lt;script&gt;x&lt;/script&gt;`），**不产标签、也不整块消失**。这与 §3「超出白名单即丢标签留文本」同向，但走的是「从未被解析成标签」的路径。

## 3. 消毒契约（白名单）

渲染函数的产物**只可能**由下列内容构成，超出即丢标签留文本：

- 标签白名单：`h1` `h2` `h3` `p` `ul` `ol` `li` `blockquote` `pre` `code` `strong` `em` `a` `img` `hr` `br` `span`
- 属性白名单：`a[href]`、`img[src]`、`img[alt]`、`span[class]`
- `span[class]` 只接受 §2.2 的 **7 个枚举名**，其余 class 一律丢弃（标签保留）
- `href` / `src` 协议白名单：**只允许 `http://` 与 `https://`**，`javascript:` / `data:` / 相对路径一律丢弃该属性
- 其余属性（`on*`、`style`、`srcset`、`target` 等）**一律丢弃**
- 文本节点转义 `&` `<` `>`（`"` `'` 在非属性位不转义）

**红线**：三端各自的渲染出口必须走同一个「解析 + 消毒」函数，**禁止**在页面 / 模板层拼接未消毒 HTML。节点门户用 `template.HTML` 关转义，是唯一一处显式绕过 Go 模板转义的地方，必须在同函数内消毒完毕再返回。

## 4. 双端同构与契约向量

- **Go 实现**：`internal/markdown/`（解析 + 消毒 + 导出 `Render(src string) template.HTML` 与 `RenderString(src string) string`）。
- **TS 实现**：`apps/mobile/src/core/markdown.ts`，导出 `renderMarkdown(src: string): string`。只依赖 `@base/protocol-ts` 与自身，**不 import 'uni'**，可在 Node 下用既有 fakes 测试。
- **共享向量**：`vectors/v1/markdown.json`，元素形如 `{ "name": "...", "src": "...", "html": "..." }`。Go test（`internal/markdown/vector_test.go`）与 vitest（`apps/mobile/src/core/markdown.test.ts`）**读同一文件**，逐条断言。
- 向量至少覆盖：§2.1 每一项、§2.2 歧义三例（链接 / 变色 / 都不匹配）、未知类名、转义、未匹配降级、§3 每一类拒绝项（含 `javascript:` 与 `onerror`）、老数据纯文本等价例。
- **漂移判据**：任一端改动导致向量不过 ⇒ 门禁红。禁止只改一端并跳过向量。

## 7. 兼容与老包（已知断层）

- **老数据**：无任何标记的正文，解析结果与现状（按空行切段 + 纯文本）**等价**，无感。
- **老 App 包（≤ `0.15.0`）**：行内标记会显示字面量（`[文字]{.c-red}` 与 `**粗**` 都会原样露出）。**这是必须接受的兼容断层**——服务端直出的 HTML 只服务门户，App 侧渲染在本地，老包不升级就看不到颜色。编辑器**不做**针对老包的降级提示（成本大于收益，本册明确不做）。
- **新包读老数据**：正常，无标记即普通段落。

## 8. 已知边界（登记，不在本册修）

1. **正文内嵌图片无上传面**：`attr.cover` / `attr.attachment` 是**条目级**槽位，正文段落没有对应的图片载体。本册只支持 `![alt](http(s)://…)` 外链；**要内嵌自有图片需另开册子**（涉及新的槽位或新的正文引用口径）。
2. **`#40` 的 `attr.body_md` 提示文案需同步**：「正文以 Markdown 源文本保存，与文章同口径」在编辑页 hint 中仍成立，但工具栏旁的说明要补「支持 `[文字]{.c-red}` 变色」。
3. **`rich-text` 的样式承载上限**：`ul` / `ol` 的缩进、`blockquote` 的左边框、`pre` 的等宽与横向滚动在 App 端由 `rich-text` 内部渲染决定，**须真机实测**；H5 通过不等于 App 通过。若 App 端表现不可接受，退路是把列表降级为「带 `·` 前缀的段落」——**退路只在真机验证后启用，不预先实现**。
4. **门户 `pre` / `code` 的高亮不做**，仅等宽字体与浅灰底。

## 12. 风险点

1. **双端漂移**（最大成本项）：Go 与 TS 两份解析器必然存在实现差异。压舱石是共享向量（§4），但**向量覆盖不到的分支仍会漂**——故解析器必须保持「无异常、纯函数、单出口」形态，且拒绝在任一端加入本地特化逻辑。
2. **消毒漏一个属性即 XSS**：门户用 `template.HTML` 关了模板转义，任何未经本函数消毒的 HTML 直通 XSS。防线是白名单最小化 + §9 AC 2 的负例集合；**新增任何属性前必须先加负例用例**。
3. **`rich-text` 在 App 端的样式承载**（§8 第 3 条）：这是本册唯一无法在本机静态判定的一项，真机实测是 AC 7，未过则启用退路。
4. **老包兼容断层**（§7）：颜色只对升级后的包可见。若未来要求「老包也不露出标记」，需要在编辑端加提示或改语法为老包可容忍的形态——**本册明确不做**，登记为已知代价。
5. **正文注水**：变色语法给了用户「到处加色」的能力。不设技术限制（不限制标记数量），但 §6 的 6 字色 + 1 底是按语义设计的，编辑器色块按钮**按语义命名**（如「强调 / 提示 / 补充」）而不是按颜色命名，以引导用法。
