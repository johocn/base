- 日期：2026-09-25（2026-09-26 重大改版：身份自持密钥、可见性三类、加密范围收敛、节点职责收敛）
- 仓库：`e:\code\base`（远端 `git@github.com:johocn/base.git`，已 `git init` 并绑定 `origin`）
- 定位：分布式、可自由分发的**课程学习 + 交流 + 互动**平台
- 节点运行时：**目标态 = TS 单核（Node.js 宿主壳）**；迁移期与 Go（静态单文件，纯 Go SQLite，无 CGO）**并行双跑**，行为等价后 Go 退役（见 §0.13）

## 0. 改版说明

### 0.1 2026-09-26 改版（本版·客户端传输改明文）

本版推翻 §0.2 的「全程 TLS」，把客户端链路与节点间链路**分开定**。

**作废内容：**

- **传输作废**：§0.2 的「客户端↔节点、节点↔节点一律 TLS」（原 §4 访问模型「传输」行、原 §12.2 TLS 信任模型）整体作废。新结论（退路 F1，2026-09-26 定案）：**客户端↔节点走明文 HTTP；TLS 只用于节点↔节点（双向 mTLS + 指纹固定）**。

**新增内容：**

- §12.2 重写为「两条链路分开定」+ **F1 的代价明细**（明文链路上被动旁观者可读 ① 类明文与请求路径；截断可阻断但不可伪造内容、不可冒用身份）。
- §12.1 的 L1 传输行收窄为「节点↔节点」，并把「客户端↔节点 TLS」移入明确不做。
- **`-tls-cert=off` 的语义边界**：只关**主监听**加密，**不关闭节点自身身份**——启用对端监听时仍从默认路径 `data/tls/node.crt|key` 生成/加载证书（否则 F1 配置下 `serve` / `scrub` / `peer-sync` 会直接报「证书与私钥路径都不能为空」）。

**保留并沿用：** 「公开即全网可复制」哲学、内容包规范 v1、节点公开读与反熵接口、手机端离线、事件与审核、交付形态铁律、迁移源契约、客户端自持 Ed25519 身份与签名头认证。

### 0.4 2026-09-29 改版（保留·手机本地库加密 spike 定案）

本版落实 #4 spike 的结论（册子：`specs/2026-09-26-base-mobile-local-encryption-spike.md`）。**总纲是唯一上游**，故先改此处。

**作废内容：**

- **§8.2 的目标句作废**：原「让 `plus.sqlite` 本地库文件在设备上以密文落盘，且用户可自由开关」整体作废。spike 结论：`plus.sqlite` 官方 API 面**没有任何加密参数**（`openDatabase(options)` 仅 `name` / `path` / `success` / `fail`）；唯一的 SQLCipher 路径是 UTS 原生插件（Android-only、需自定义基座、iOS 不支持），**超出「纯 uni-app、无原生代码」的既定预算**——与 #3 否决 F2 的理由逐字同构。
- **§12.1 的 L3 行作废**：原「`plus.sqlite` | 可开关；实现待 spike，含退路 | **做**」改为应用层列级加密的定案形态。
- **§12 第 11 条作废**：原「本地库加密密钥派生自本机私钥」在逻辑上**不可实现**——私钥自身由 KEK 加密，KEK 若再由私钥派生即鸡生蛋死锁。改为「KEK 为设备随机密钥，不派生自私钥」。

**新增内容：**

- **退路定案：应用层列级加密**（原 §8.2 退路 ① 与 ② 本是同一种技术，差别只在覆盖面，现统一表述）。覆盖面：身份私钥（已落地）/ 组密钥（待 #9）/ 私信正文本地持久化（待 #10）；**① 类公开内容保持明文**——本地加密对公开内容隐私收益为零，只会把「重装后重新下载」变成唯一路径。
- **`kek_source='device'` 定案**：随机 32 字节存应用私有存储。`KekSource` 三值枚举一个不删，含义从「待收敛」改为「已定案，保留升级位」（口令派生 / 设备安全存储均为将来可选，本册不实施）。
- **§8.2 新增红线**：全面禁止 `PRAGMA key` / `PRAGMA rekey` / `PRAGMA hexkey`——`plus.sqlite` 用平台普通 SQLite，未识别 PRAGMA 会被**静默忽略**，误加会产出「看起来已加密、实际明文」的库，比不加密更危险。
- **「用户可自由开关」一并搁置**：开关的动机是「担心加密影响性能/兼容」，库级加密不做则失去目标物；且不为敏感字段加密提供关闭开关（私钥密文落盘是安全底线）。现状即如此，**代码零改动**。

**保留并沿用：** 私钥永不落明文与 `identity.privkey_cipher` 的 `nonce:ct` 形态、`saveLocalIdentity` / `loadLocalIdentity` 契约与「只替换 `deviceKek()` 一个实现」的重构点、§12 第 10 条「必须提供私钥导出/备份」与 §8.2 的「重装降级路径」（这两条**继续有效**，归 #11 运维文档落地）、① 类公开内容不做本地加密。

### 0.5 2026-09-29 改版（保留·学习小组 ② 加密定案）

本版落实 #9 册子（`specs/2026-09-29-base-groups-design.md`）。新增内容全部与既有契约兼容，**无作废项**。

**新增内容：**

- **小组标识与锚定**：`group_id` 由客户端生成 16 hex 随机（与 `event_id` 同形，**不由组密钥派生**——否则轮换即换组）；`target_id` 形态 `group/<group_id>`，沿用 §6.0 路径式命名空间。
- **组密钥与 epoch**：32 字节随机，一 epoch 一把密钥；**加入不换钥，移出才轮换**（新 epoch 组密钥 + 创建者签名的 `roster` 事件，经带外续期码送达剩余成员）。
- **新事件类型 `group.v1`**：`action=msg`（密文发言——节点按 `BlobID(密文)` 落块 + 落事件行、**不解密**）与 `action=roster`（创建者签名完整名单快照，节点验 owner 锁与 epoch 单调递增）。**不新开 blob 上传面**：② 类密文只能作为事件的一部分进入节点。
- **新公开读接口 `GET /v1/group/{group_id}?cursor=&limit=`**：匿名分页读索引与当前名单，体例与 `GET /v1/comment` 一致（游标 `<created_at>_<event_id>`、满页才给 `next_cursor`）。**代价写明**：索引匿名可读 ⇒「谁、何时、在哪个组发言」这一层元数据公开；内容仍不可读。
- **节点侧唯一新状态** `groups(group_id, creator_id, epoch, member_ids_json, event_id, updated_at)`：只含 id 列表与 epoch，**不含密钥、不解密内容**——§3.1「节点只存成员名单（id 列表）」的落地形态，同时承载创建者 owner 锁。
- **本地表新增 `group_keys(group_id, epoch, key_cipher)`**：历次 epoch 组密钥，按 §0.4（#4）定案走**应用层列级加密**，复用 `deviceKek()`（`kek_source='device'`），不新增 KEK 种类；`groups` 行改为 `groups(group_id, name, creator_id, epoch, member_ids_json, joined_at)`。
- **反熵与事件传播零改动**：`POST /v1/event-sync` 不按 type 过滤、反熵只比对 `blob_id`，故小组事件与 ② 类密文块**自动跨节点传播**（§7.4 原文已覆盖）。审核通道对 ② 类取到的仍是密文，**不提供解密**。

**保留并沿用：** ② 类「节点不可读、不可审」（§12 第 9 条）、`POST /v1/event` 的验签管线与「先验签、后落块」次序、`comment_out` 离线队列（小组发言复用，**零新表**）、内容包规范 v1（小组消息不进包、**不 bump `schema_version`**）、① 类公开读全部口径。

**已知边界（本版确认接受，不视为缺陷）：** 无前向安全（旧 epoch 密钥留存本地，被移出者仍可解移出前消息）；轮换送达依赖带外可达（长期离线成员静默读不出新消息，客户端**必须**显式提示「小组密钥已更新」）；创建者丢钥即名单冻结（无转让机制）；邀请码含密钥且无有效期。

### 0.7 2026-09-29 治理体系重规划（两层治理）

本版落实 #33 册子（`specs/2026-09-29-base-governance-circle-design.md`），一次补齐**两层治理**：**L2 圈子自治**（隔离 · 席位 · 门槛 · 轮换 · 多签）与 **L1 全局治理一致性**（`govern.v1` 事件化 · 名册快照水位 · 确定性收敛）。**总纲是唯一上游**，故先改此处（铁律 1）。

**动机**：治理主线四册（#23 / #25 / #27 / #29）的治理是**「本节点自治」**——名册由各节点自行派生、提案与投票只在本地生效、结论靠「导出 / 导入内容包」间接传播（#28 AC 13）；同时 #9 小组把「成员准入读控制」明确排除（索引匿名可读为记录在案的代价）。本版一次补上跨节点一致性与圈子自治与隔离。

**作废什么：**

* **#27 的「票实时复判」作废**：被**提案快照水位**取代——票权按提案建立时的名册水位 `(content_version, revoked_rev)` 判定，不按实时名册复判（§6.5）。
* **#9 的「不做成员准入读控制」这条代价作废（已收口）**：封闭圈改走**成员签名读权**（非成员 `404`），该条代价不再成立（§3、§3.1、§4、§7.3）。

**新增什么：**

* **圈子形态二元化**：**开放圈**（**不加密** · 匿名可读 · 自助自加入）与**封闭圈**（加密 · 成员签名读权 · 邀请码带密钥），形态**建圈时定死、不可切换**（§3、§4）。
* **治理人席位阶梯**：`k(m) = 1`（m ≤ 10）；`k(m) = min(10, 3 + ⌊(m−11)/10⌋)`（m > 10）；席位构成 = **创建者永久 1 席 + 其余按圈内贡献度排名补足**。
* **圈内贡献度排名算法**：只数已验签 `group.v1` 的 `action=msg` 事件条数；按 `event_id` 去重；同一 actor 任意滚动 24h 最多计 20 条；只统计当前成员；`count` 降序、同分按 `actor_id` hex 字典序升序；第 k 与第 k+1 同分取 id 小者；附带快照水位 `(roster_rev, event_watermark)`；事件不齐时返回「不可判定」，不猜名次。
* **多签生效**（节点验签、**不数票**）+ **门槛三档**：低风险（改名 / 主动轮换 / 自己退出）= 任一治者 1 签；签发邀请码 = 任一在册成员（无门槛）；**移出成员 = 治者 ≥ `⌈2k/3⌉`**（k = 1 时自动 1 签）；**解散圈子 = 两段式：发起 = 治者 ≥ `min(2, k)` 名联署；通过 = 成员 ≥ `min(30, ⌊m/3⌋+1)`**（必须超过 1/3，上限 30 人）。治者签名在同一提案上可同时计入发起集合与成员投票集合。
* **密钥「成员集合任一变更即轮换」+ 对称信封链**：加入 / 移出 / 重新加入即 bump `epoch`；加入携带当前 + 历史 epoch 密钥（上限 32 个 epoch）；移出者对后续不可读；轮换新钥用旧钥逐成员 AEAD 加密成信封，随 `action=roster` 的 `envelopes[]` 走节点，**节点不持有密钥**。
* **L1 `govern.v1` 事件化 + 快照水位**：`action=proposal` / `action=vote`，**沿用通用事件内容签名 `canonical({event_id,type,created_at,body})`，不新增签名域常量**（2026-09-29 口径收口，见治理册 #33 §0.2 第 3 条）；反熵**零改动**（不按 type 过滤）；票权按提案建立时的名册水位 `(content_version, revoked_rev)` 判定；并发按 `(created_at, event_id)` 取首、票按 `(proposal_id, voter)` 取最早；门槛沿用 #27（`remove` 3 票、`edit` / `revive` 2 票）；`govern_*` 两表降级为投影，老路径 `POST /v1/proposal` 保留、只写本地投影（**不产事件**）（§6.5、§7.3、§8.1）。

**保留什么：**

* **密码学零新算法**：继续 Ed25519 签名 + AES-256-GCM（`sealWithNonce` / `openWithNonce`），**不引入 X25519** 或任何非对称加密。
* **节点永不持有组密钥、不解密 ② 类正文**（§12 第 9 条 + 本版新增第 13 条）。
* **① 类公开内容与评论链路**、**块仍匿名可取**（§4、本版新增第 15 条）。

### 0.8 2026-09-29 课程分类与统一标签（#36 / #37 两册）

本版为「课程分类」与「统一标签体系」两册同步扩 §6.0 的内容模型取值集合。**总纲是唯一上游**，故先改此处（铁律 1）。

**作废什么：** 无。本版**不推翻任何既有条款**，只把 §6.0 的取值集合与形态表扩两个值。

**新增什么：**

* **§6.0 的 `source` / `type` 取值集合各扩两个值**：`category`（课程分类容器）与 `tag`（统一标签条目）。两者都**借 `segments` 承载**（`sqlite_table = segments`），**不新增表、不新增字段**。
* **item_id 形态新增两条**：`category/<slug>`（分类的单级扁平容器，其 `segments` 清单列出该分类下的 `course/<cid>`）与 `tag/<名称>/<章>/<节>`（标签三元组直接编码进 `item_id`，唯一性由此天然成立）。
* **标签关联的权威落在节点侧新表 `tag_links(tag_id, target_id, kind)`**，`kind ∈ course | lesson | article | comment`。**该表不进内容包**：标签条目的 `segments` 行是同一次写入的**确定性物化**（写入时同一事务落投影行，排序口径见 #37 §3.3），导出直接走既有 `segments` 分支；手机端同步后据这些行回填本地 `tag_links` 派生表（内容包规范 v1 **零改动、不 bump `schema_version`**）。

## 1. 目标

让学习者用手机 App 访问「公开可分发内容」（课程、文章、题库等），把内容下载到本地随时离线学习；在内容之上进行讨论、打卡与小组协作，并可互发私信。内容在多个节点间分布存储，节点消失后可由邻居按内容哈希补齐。

**节点不是权威，是登记与缓存。** 节点收敛为两项不可替代职责：

1. **id 登记**：把内容 id、身份公钥 id、事件 id 与其签名登记到本地索引，并可通过 `inventory` 与邻居互相核对。id 本身由哈希或公钥派生，**不依赖任何节点分配**——登记只是「记录下来并可被核对」，不是「发号」。
2. **版本对齐**：以签名的 `content_version` 为准做新旧裁决，保证任意两节点最终收敛到同一版本视图。

内容分发（拉包、存块、供读、反熵补齐）是**可替代的缓存职能**——任一节点消失，其余节点按哈希补齐即可，不影响 id 与版本的正确性。

节点是同构的：**谁愿意贡献服务器或自己的电脑，从仓库取源码或发行包部署，谁就成为一个节点。**

## 2. 明确不做（排除范围）

- 不做区块链、共识、token、DHT。所谓「区块链式」只体现为哈希寻址 + Merkle 清单 + 多副本。
- 不承载受控内容（需鉴权/付费/内部内容）：这类内容不属于本系统，不迁移、不存储、不转发。
- **不由节点签发身份**：节点不生成密钥、不托管明文私钥、不发放 JWT。
- **不做 L4b / L4c 两类应用层加密**（全网共享密钥 / 每节点独立密钥 + 跨节点重加密），也**不做 ① 类公开内容的端到端加密**——理由与不可达边界见 §12.1。节点磁盘的 **L4a′ 应用层静态加密做**（§12.1.1）。
- 二期前不做 iOS（离线文件与后台下载受限）。

## 3. 可见性分界（三类）

| 维度 | ① 公开可分发 | ② 加密可分发 | ③ 受控内容 |
|---|---|---|---|
| 内容举例 | 课程、文章、题库、公开讨论 | 私信、小组内讨论 | 需授权/付费/内部内容 |
| 小组（圈子）的两种形态（2026-09-29 §0.7 补） | 不适用 | **封闭圈**：加密分块 · **成员签名读权**（非成员 `404`，不泄露存在性）／ **开放圈**：**不加密**（明文，同 ① 类）· **匿名可读** · 自助自加入；形态**建圈定死、不可切换** | 不属于本系统 |
| 是否进本系统 | 是 | 是 | **否，完全不碰** |
| 存储形态 | 明文分块 | 密文分块（客户端 E2E 加密后落库） | 不属于本系统 |
| 读取要求 | 匿名可读，无需登录 | 仅持解密密钥的参与者可读 | 不属于本系统 |
| 复制 / 近场互传 | 允许，节点可任意缓存 | 允许复制字节，但无密钥不可读 | 不允许分发 |
| 节点能否理解内容 | 能（明文） | **不能**（不透明密文） | — |
| 审核 | 先发后审 + 审核通道 | **不可审**（见 §12 第 9 条） | — |

铁律：

1. 只有 ① ② 两类内容的字节可进入内容库、内容包、节点块目录与客户端本地库；③ 类一律不得进入。
2. ① 类不加密、不鉴权、允许任意复制与近场互传。**① 类等于全网可复制转存，这是模式固有前提，不是缺陷。**
3. ② 类的密文对节点是**不透明字节**：可存储、可复制、可反熵、可参与副本因子，但节点**不得尝试解密、不得索引其明文、不得为其建立任何明文派生索引**。
4. ② 类的密钥分发、成员名单与密钥轮换由客户端负责。节点只判断「谁有权取这份密文」（访问控制），不判断「内容是什么」。
5. 可见性标签在源节点导入/发布时判定，结果写入签名 `manifest`。改标签 = 发一个新 `content_version`，不得原地改。

### 3.2 寻址域 / 存储域解耦（新增护栏）

- **寻址域（不可变契约）**：`blob_id = hex(sha256(逻辑字节))[0:32]`（128 bit）。
  - ① 类：逻辑字节 = 明文。
  - ② 类：逻辑字节 = **密文**。加密先在客户端完成，**先定密文、再算 id**。
  - 评论/事件正文同样按此寻址，事件字段 `payload_cid` 即该 `blob_id`，两者是同一个 id。
- **存储域（可替换实现）**：磁盘上到底放明文、放密文、放压缩字节、还是放在文件系统级加密的容器里，属于节点本地实现细节。
- **护栏**：任何人、任何版本、任何性能优化，**不得修改 `blob_id` 的算法与其输入**。去重、秒传、副本因子、反熵、Merkle 清单五项全部建立在「同一逻辑字节必得同一 id」之上；改算法即同时破坏这五项，且不可逆（历史 id 全部失配）。
- 由此得到一条重要性质：**节点磁盘静态加密不破坏寻址**——磁盘表示变了，`blob_id` 不变。这是 L4a 与 L4a′（§12.1）成立的前提。
- 节点磁盘布局：`data/blobs/<h0..1>/<h2..3>/<blob_id>`。内容寻址 → 任何来源的块天然可验真，内容一变哈希即变。**因此不需要共识与链。**

## 4. 访问模型

| 操作 | 要求 |
|---|---|
| 读：`catalog` / `manifest` / `pack` / `blob` / 浏览页 | 匿名开放，无需登录。② 类密文同样可匿名取字节，但无密钥不可读。**`GET /v1/blob/{cid}` 密文块仍匿名可取**（内容寻址、被 ① 类复用，**不做逐块鉴权**）；**`GET /v1/group/{group_id}` 按形态分支**（2026-09-29 §0.7 补）：开放圈匿名读；封闭圈需**成员签名读权**；**非成员一律 `404`**（不泄露存在性） |
| 写：评论、进度、小组、私信 | **客户端自持 Ed25519 密钥签名**；请求携带「公钥派生 id + 签名」（签名头，见 §7.3）；时间窗 300s + nonce 防重放。**节点不签发身份、不发放 JWT** |
| 身份锚定（可选）：用户名 + 密码 | 节点托管「用密码派生密钥加密后的私钥」**密文**。节点永不接触明文私钥，也不知道密码 |
| 节点间：`inventory` / `sync` / `fetch` / `scrub` | 预共享密钥（`X-Base-Node-Key`），不对外 |
| 传输 | **两条链路分开定**：客户端↔节点 = **明文 HTTP**；节点↔节点 = **TLS + 双向 mTLS + 指纹固定**。信任模型与 F1 代价见 §12.2 |
| 审核取正文 | 审核密钥，仅运营侧；**仅适用于 ① 类**。② 类节点无密钥，无法审核 |

**guest 路径**：未注册用户打开 App 即可浏览目录、下载与离线学习全部 ① 类内容。需要发评论、记进度、入小组、发私信时，App **本地生成密钥对即可**，无需注册、无需等待节点审批。用户名 + 密码是「换设备取回私钥」的**可选便利**，不是使用的先决条件。

## 5. 系统构成

```
协议规范层  vectors/         （语言中立的黄金测试向量，Go 与 TS 共用）
节点服务    Node.js 宿主壳   （**目标态**；迁移期 Go 单进程 cmd/based 并行双跑 —— 见 §0.13 / #69 §3）
手机端      apps/mobile      （uni-app，Android 优先）
迁移工具    tools/migrate    （一次性：Strapi REST → base 内容库）
发布脚本    scripts/         （交叉编译 + 一键安装脚本）
```

> **迁移期标注（§0.13）**：「节点服务」与「手机端」**不是两套系统**，而是**同一份 core 的两个宿主壳**。上表当前由 Go 单进程承担节点侧；目标态为 TS 单核 + Node 宿主壳，二者并行双跑，行为等价后 Go 退役。

### 5.1 仓库目录结构

```
base/
  vectors/                     # 黄金测试向量（JSON，语言中立）
  go.mod
  cmd/based/                   # 节点主程序入口
  internal/protocol/           # Go 协议实现：canonical JSON / sha256 / Merkle / Ed25519
  internal/store/              # SQLite 访问层（modernc.org/sqlite）
  internal/httpapi/            # 公开读 / 写 / 内部同步 / 审核 接口
  internal/sync/               # 反熵、补齐、scrub
  internal/auth/               # 身份：公钥→id 派生、事件验签、密码托管私钥密文存取（Ed25519，无 JWT）
  web/                         # 节点自带只读浏览页（html/template + 少量原生 JS，内嵌）
  tools/migrate/               # 一次性迁移工具
  packages/protocol-ts/        # TS 协议核（目标态：手机壳与 Node 壳共用的**单份**实现）
  apps/mobile/                 # uni-app
  scripts/                     # build-release.ps1 / install.sh / install.ps1
  docs/
```

> **迁移期标注（§0.13）**：`cmd/based/`、`internal/*` 与 `go.mod` 是**迁移期**的 Go 节点实现。目标态下协议与业务核心收敛为**单份 TS**（`packages/protocol-ts/` 已是协议核，业务核另立包），手机壳与 Node 宿主壳只换注入实现。Go 目录**保留至并行双跑结束**，不提前删除。

### 5.2 与 Strapi / basic 的关系

- 内容来自**一次性迁移**：`tools/migrate` 通过 Strapi REST 读取课程、文章、题库，写入 base 内容库；迁移完成后两边零依赖、零同步。
- 身份不迁移、不复用：base 采用客户端自持密钥模型，历史 SSO 用户与积分体系不连通。
- 迁移是单向、可重跑的工具，不在运行时依赖 Strapi。

### 5.3 协议双实现与对齐机制（**迁移期状态**）

> **§0.13 标注**：本节描述的是**迁移期状态**，不是目标态。目标态为 **TS/JS 单实现**（同核双形态：手机壳与 Node 壳共用同一份 core）。下列「Go / TS 两份实现」在**并行双跑期**继续成立；**对齐铁律**（`vectors/` 逐向量双端消费）在迁移期继续作为**漂移门禁**执行，Go 退休后收敛为单端消费。

协议存在两份实现，必须行为一致：

| 实现 | 位置 | 用途 |
|---|---|---|
| Go | `internal/protocol` | 节点：签名、导出包、校验 |
| TS | `packages/protocol-ts` | 手机端：验签、内容哈希与 Merkle 校验、读 pack |

**对齐铁律**：`vectors/` 下每个向量（固定私钥 + 固定输入 + 期望 canonical 字节 + 期望 `merkle_root` + 期望签名）必须被 Go 与 TS 两侧的测试同时消费。任何一侧漂移即测试失败。Ed25519（RFC 8032）签名确定性，同一密钥与消息的签名可作黄金值。

## 6. 内容包规范 v1

### 6.0 内容模型：课程体系

课程体系为 `category → course → lesson → (article | video | quiz)`；**统一标签（`tag`）与课程体系正交**（2026-09-29 §0.8 补）。

| 层级 | 说明 |
|---|---|
| category | 课程分类：**单级扁平容器**，`segments` 清单列出该分类下的 `course/<cid>`（一课程至多属一分类，2026-09-29 §0.8 补） |
| tag | 统一标签：`名称 / 章 / 节` 三元组构成的一位条目；与 course / lesson / article / comment 的关联由节点侧 `tag_links` 承载（权威表），并同事务物化进该条目的 `segments` 行随包传播（2026-09-29 §0.8 补） |
| course | 课程：标题、简介、封面、课时归属 |
| lesson | 课时：属于某个 course，承载 1..n 个载体条目 |
| article | 图文正文（`body_md` + `segments`） |
| video | 视频（`media_meta` + 分块） |
| quiz | 题组（`question_json`） |

归属关系用 **`item_id` 的路径式命名空间**表达，manifest 保持扁平，不新增表、不新增字段：

```
category/<slug>                   # 课程分类；其 segments 清单列该分类下的 course/<cid>
tag/<名称>/<章>/<节>               # 统一标签；三段直接编码进 item_id，唯一性天然成立
course/<cid>
course/<cid>/lesson/<lid>
course/<cid>/lesson/<lid>/article/<aid>
course/<cid>/lesson/<lid>/video/<vid>
course/<cid>/lesson/<lid>/quiz/<qid>
article/<aid>                     # 不属于任何课程的独立文章
```

- `manifest.entries[].source` 沿用既有取值 `course` / `lesson` / `article` / `quiz`，**2026-09-29 §0.8 扩入 `category` / `tag`**；视频条目 `source` 记为 `lesson` + `type=video`，不新增 `video` 枚举值。
- 前缀即归属：按 `<cid>/` 前缀扫描即得该课程的全部课时与载体，无需递归查询。
- P0 每个 lesson 只承载单个载体，**不引入排序字段**；需要课时内排序时在 A 阶段通过 `lesson` 条目的内容表达。
- 层级只表达「归属与顺序」，**不表达权限**。权限与可见性一律由 §3 的 `dist_class` 承载。

### 6.1 `manifest.json`

| 字段 | 说明 |
|---|---|
| `pack_id` | 包标识 |
| `schema_version` | 固定 `1` |
| `issuer` | 签发方标识（源节点 id） |
| `issued_at` | 签发时间 |
| `content_version` | **全局**单调递增（每次导出 +1），冲突时大者胜 |
| `entries[]` | 条目清单 |
| `tombstone[]` | 撤回清单 `{item_id, revoked_rev}` |
| `merkle_root` | 所有 `blob_id` 排序后构树的根 |
| `signature` | Ed25519 签名（覆盖上述字段的规范化 JSON） |

`entries[]` 单项：

| 字段 | 说明 |
|---|---|
| `item_id` | 条目 id（路径式命名空间，见 §6.0） |
| `source` | 来源模块：`course` / `lesson` / `article` / `quiz` / `category` / `tag`（后两个 2026-09-29 §0.8 补） |
| `type` | `article` / `video` / `quiz` / `subtitle` / `cover` / `category` / `tag`（后两个 2026-09-29 §0.8 补） |
| `title` | 标题 |
| `source_rev` | 源内容版本 |
| `content_hash` | 条目级哈希 |
| `sqlite_table` | 落在 `pack.sqlite` 的表名；视频类为 `media_meta` |
| `chunks[]` | 视频条目：`{blob_id, size, seq}` |
| `dist_class` | **可见性标签**：`public`（① 公开可分发）/ `encrypted`（② 加密可分发） |

manifest 中**没有**权限标签、用户范围、过期时间。`dist_class` 是可见性分类，不是授权。

### 6.2 `pack.sqlite`

| 表 | 用途 |
|---|---|
| `articles(item_id, title, digest, published_at, tags_json, body_md, content_hash, source_rev)` | 文章正文 |
| `segments(item_id, seq, kind, text, content_hash)` | 文章分段 / 字幕 / 讲义片段 |
| `quizzes(item_id, question_json, content_hash)` | 题库 |
| `media_meta(item_id, mime, size, duration, chunk_size, chunk_hashes_json)` | 视频元数据与分块索引 |
| `meta(key, value)` | `pack_id` / `content_version` / `merkle_root` |

`pack.sqlite` 由源节点从内容库导出，是**只读分发产物**；导出为确定性过程（同版本内容导出字节一致）。② 类内容不进 `pack.sqlite`（其正文只在客户端有明文）。

### 6.3 块与寻址

见 §3.2。要点复述：视频按定长 1 MiB 分块，文本与小资源整块处理；`blob_id` 算法不可变；磁盘布局 `data/blobs/<h0..1>/<h2..3>/<blob_id>`。

### 6.4 签名与验签

源节点用 Ed25519 私钥签 `manifest`；客户端与所有节点内置公钥验签。验签失败 → 整包拒绝。manifest 与 `pack.sqlite` 的行级 `content_hash` 双重校验，任一不符即判坏块。

### 6.5 版本与墓碑

- 导出触发：源节点手动或定时导出增量包，并递增全局 `content_version`。
- 内容更新 → `content_version` 递增，客户端按版本覆盖本地。
- 内容下架/删除 → 新版本 manifest 带 `tombstone`；客户端同步时删除对应本地行与块；节点同样删除，且墓碑**只能在签名 manifest 中传播**，节点无法伪造。
- **可见性变更（①↔②）= 新 `content_version` + 新 `item_id`**：② 类密文与 ① 类明文的 `blob_id` 必然不同，不构成原地修改。
- **治理结论跨节点一致（2026-09-29 §0.7 补）**：他人条目的 `remove` / `edit` / `revive` 三动作事件化为 **`govern.v1`**（`action=proposal` / `action=vote`，**沿用通用事件内容签名 `canonical({event_id,type,created_at,body})`，不新增签名域常量**），随反熵跨节点传播 ⇒ 结论**不再依赖内容包导出 / 导入**即可收敛。**票权按提案建立时的名册快照水位 `(content_version, revoked_rev)` 判定，不按实时名册**（修正 #27 的「票实时复判」）；并发提案按 `(created_at, event_id)` 取首、票按 `(proposal_id, voter)` 取最早；门槛沿用 #27（`remove` 3 票、`edit` / `revive` 2 票）。`govern_proposals` / `govern_votes` 降级为本地物化视图（加可空 `source_event_id`），老路径 `POST /v1/proposal` 保留、只写本地投影（**不产事件**）。

## 7. 节点设计

### 7.1 同构部署与职责

所有节点部署物完全相同（同一个静态二进制），职责由配置决定：

| 职责 | 是否可替代 | 配置特征 | 能力 |
|---|---|---|---|
| **id 登记 + 版本对齐**（权威） | 不可替代 | 持签名私钥（`BASE_SIGN_KEY`） | 导入/编辑内容、判定 `dist_class`、递增并签发 `content_version`、签发墓碑、登记身份公钥 id 与事件 id |
| **内容缓存与分发**（可替代） | 可替代 | 不配置私钥 | 拉取已签名内容包与块、存块、匿名供读、与邻居反熵补齐、scrub |

铁律：

- **没有私钥就不可能产出新的、可被验签的内容版本**（内容不可伪造）。
- **没有缓存能力不影响 id 与版本的正确性**（节点消失可由邻居补齐）。

这两条同时成立，才使「谁都能当节点」与「内容不可伪造」不矛盾。

### 7.2 目录布局

```
data/base.db            # 内容库 / 索引 / 事件 / 副本登记 / 身份公钥登记 / 托管私钥密文
data/blobs/xx/yy/<id>   # 块文件
data/packs/<pack_id>/   # 已发布包（manifest.json + pack.sqlite）
data/tls/node.crt|key   # 节点自签证书与私钥（§12.2）
data.key                # L4a′ 节点静态加密密钥（0600）——data 的兄弟文件，**不在 data 目录内**
```

`data.key` 刻意放在 `data/` 之外：备份脚本、对象存储同步、`cp -r data` 都不应连密钥一起拷走。代价与残余风险（备份**整个安装目录**仍可解密）见 §12.1.1。

### 7.4 反熵与节点恢复

1. 节点每 5 分钟向邻居取 Merkle root。
2. root 相同 → 本轮回合结束。
3. root 不同 → 拉邻居 inventory 分页，比对本地集合，得出 `missing` / `extra`。
4. `missing` → `POST /v1/fetch` 批量拉取 → 逐块重算 sha256 校验 → 入库 → 更新本地副本登记。
5. `extra` 仅记录，不主动删除（避免误删唯一副本）。

**恢复语义**：节点消失后不需要投票、不需要重建链——剩余节点或客户端查副本清单/邻居清单，发现该哈希仍有人持有即拉回，校验通过即恢复。只要全网还有 1 份副本就能恢复。副本因子默认 2：某块登记位置少于 2 时，节点主动向邻居补齐；淘汰块前必须确认别处存在副本。

② 类密文以同样的机制参与反熵与副本因子：节点比对的是 `blob_id`，**不需要也无法读取内容**。

### 7.5 scrub 自愈

每日全量重算哈希，发现坏块 → 删除本地副本 → 从邻居补齐 → 更新副本登记。② 类密文只需重算密文哈希，无需解密。

### 7.6 交付形态铁律

- 节点以 **Go 静态单文件**（`CGO_ENABLED=0`，`modernc.org/sqlite` 纯 Go 实现）发布，交叉编译覆盖 `linux/amd64`、`linux/arm64`、`windows/amd64`。
- 贡献者路径只有两条，都**不需要他装运行时、不需要现场编译**：① 运行 `scripts/install.sh` / `install.ps1` 下载对应平台发行二进制；② 自行 `go build`（仅对已装 Go 工具链者）。
- 构建与交叉编译一律在开发机完成，服务器只接收二进制与配置；**禁止让部署者现场 `npm install` / `go get` 拉起依赖树**（历史的 2G 服务器 OOM 教训）。

## 8. 手机端设计

### 8.1 本地存储与密钥

本地库用 `plus.sqlite`，块下载用 `plus.downloader`，块文件存应用私有目录。

### 8.2 本地库加密（2026-09-29 spike 定案，见 §0.4）

**结论：库级加密不做（不可达）；改走应用层列级加密。** 定案册子：`specs/2026-09-26-base-mobile-local-encryption-spike.md`。

- **为什么不可达**：`plus.sqlite` 的 `openDatabase(options)` 只有 `name` / `path` / `success` / `fail` 四个参数，无任何加密入口；SQLCipher 在 uni-app 里只能用 UTS 原生插件（Android-only、需自定义基座、iOS 不支持），超出「纯 uni-app、无原生代码」的既定预算（同 #3 否决 F2 的理由）。
- **定案形态：应用层列级加密**——敏感字段在写入前于客户端加密、读时解密。原「退路 ①（敏感表单独加密列）」与「退路 ②（仅加密私钥与组密钥）」**本是同一种技术**，差别只在覆盖面，故不再两档并列。
- **覆盖面**：

  | 对象 | 形态 | 状态 |
  |---|---|---|
  | 身份私钥 `identity.privkey_cipher` | 密文列（`nonce:ct`） | S1 已落地 |
  | 组密钥 | 密文列 | 待 #9 |
  | 私信正文（本地持久化） | 密文存储、读时解密 | **不适用**（2026-09-29 §0.6：私信册子不缓存正文；该形态延期不取消） |
  | ① 类公开内容（`items` / 块文件） | **保持明文** | 定案不改 |

- **① 类不加密的理由**：公开内容本地加密隐私收益为零，却把「重装后重新下载 ① 类内容」从可选降级路径变成唯一路径，并给每次读取加一次解密成本。
- **密钥来源（2026-09-29 定案）**：`kek_source = 'device'`——随机 32 字节存应用私有存储（键 `identity.device_kek`）。**不引入用户口令，不引入设备安全存储**；`KekSource` 的三值枚举全部保留作将来升级位。原「由本机私钥派生」的表述**作废**：私钥自身由 KEK 加密，KEK 若再由私钥派生即死锁（详见册子 §4.2）。
- **开关（2026-09-29 搁置）**：原「用户可自由开关」随库级加密一并搁置（开关的动机是担心性能/兼容，库级加密不做即失去目标物）；且**不为敏感字段加密提供关闭开关**——私钥密文落盘是安全底线。
- **红线**：全面禁止 `PRAGMA key` / `PRAGMA rekey` / `PRAGMA hexkey`。`plus.sqlite` 用平台普通 SQLite，未识别 PRAGMA 会被**静默忽略**，误加会产出「看起来已加密、实际明文」的库——比不加密更危险。
- **残余风险（照实承认）**：KEK 与密文同库，**不抗 root / 越狱的本地读取**，此层只挡应用沙箱外的普通读取与跨设备拷贝；`plus.sqlite` 库文件本身仍是明文，② 类安全性靠「写入前已由客户端加密」而非本地库加密。
- **必须提供的退路（继续有效，归 #11 运维文档落地）**：私钥导出/备份（助记词或二维码），以及「重装后重新从节点下载 ① 类内容」的降级路径。**KEK 无备份，私钥丢失 = 本地密文不可读**。

### 8.3 下载与离线

1. `GET /v1/catalog` → 与本地 `items` 比对差异。
2. `GET /v1/pack/:pack_id` → 解包写入本地表，逐行校验 `content_hash`。
3. 视频块按需或预下载：`GET /v1/blob/:blob_id` → 写入应用私有目录（文件名=哈希）→ 校验 → 写 `blob_index`；中断由 `downloads.offset` 续传。
4. 离线阅读只读本地表 + 本地块文件，零网络。

### 8.4 近场互传（C 阶段）

热点或局域网内一方起本地 HTTP 服务，双方交换块清单：命中即秒传（只比哈希），缺失才拉块。不做 DHT、不做蓝牙。② 类密文同样可互传——传的是密文，无密钥方拿不到明文。

## 9. 学习交流 / 学习互动 / 学习进度

四类形态全在范围内，分期实施：

| 形态 | 锚定对象 | 可见性 | 载体 |
|---|---|---|---|
| 内容锚定讨论 | `item_id`（course/lesson/article/video/quiz） | ① 公开可分发 | 事件 + 正文 blob（明文） |
| 学习进度与打卡 | `item_id` + 学习者 id | 私有（仅本人可读）；**「可选公开」延期不取消**（#8 §2 第 1 条） | 进度事件（LWW 合并） |
| 学习小组 / 圈子 | `group/<group_id>` | **封闭圈 = ② 加密可分发；开放圈 = 公开可分发（不加密）** | `group.v1` 事件（`msg` 密文 blob（封闭圈）/ 明文 blob（开放圈） / `roster` **多签**名单 + 密钥信封）+ 组密钥（epoch，本地密文列）；**读权按形态分支**：开放圈匿名可读、封闭圈成员签名读权、非成员 `404`（2026-09-29 治理册子收口，见 §0.7） |
| 私信 | 收件人 id | ② 加密可分发 | 密文 blob + 收发双方 id |

- 事件通用结构（2026-09-27 按落地订正）：线上形态为 `{event_id, type, created_at, body}`；`body` 承载目标与载荷，`body.reply_to` 即原 `causal_parent`；`actor` = 签名头的 `id`（客户端公钥派生）；**`event_id` 由客户端自带（16 hex），节点只登记、不签发**。正文作为 blob 存节点。归属证明用**与请求无关的内容签名** `sig`（覆盖 `canonical({event_id,type,created_at,body})`），因为签名头绑定了 ts/nonce，事件搬到别的节点后无法重验。
- **① 类讨论**：正文按 `payload_cid` 公开可读（同 `GET /v1/blob/:blob_id`），不做读取鉴权（先发后审 + 审核通道）。
- **② 类（小组 / 私信）**：正文**在客户端加密后**才产生 `blob_id`。节点只见密文与收发方 id，可存取、可反熵、**不可读、不可审**。审核不适用于 ② 类是隐私的明确代价，须写入隐私政策。（**例外**：开放圈为公开形态、不加密，其消息按 ① 类口径处理，见 §0.7 与 §9 形态表。）
- 写路径（2026-09-27 按落地订正）：客户端 `POST /v1/event`（签名头管准入 + 事件体内容签名 `sig` 管归属）→ 节点验签 → 存正文 blob（① 明文 / ② 密文）→ 落事件行（`event_id` 由客户端自带）→ 反熵时经 `POST /v1/event-sync` 传播邻居。
- **身份**：`internal/auth` 只做「公钥 → id 派生 + 事件验签 + 密码托管密文存取」，**不签发 JWT**。节点之间互信不依赖身份签名，靠 `X-Base-Node-Key`。
- 分享归因：分享链接携带 `share_id`，只记 id 与点击；guest 分享仅统计，携带身份签名后可计入奖励。
- 审核：先发后审（仅 ① 类）。运营经审核通道按 `payload_cid` 取正文；结论 `rejected` → 删块 + 写入墓碑 → 客户端下次同步删除。
- 合并规则：内容以源节点签名的 `content_version` 为准（大者胜）；事件按因果序 + LWW 合并；② 类密文按 `blob_id` 去重（相同密文天然同 id）。

**`progress.v1` 事件语义（2026-10-01 §0.11 追加，#8 细节归该册）**：

- **body 形状**：`{item_id, position, done, day}`，**不带正文块**（`payload_cid` 为空）。`item_id` 32 hex；`position` int `>= 0`（量纲按条目 `type` 分派，见下）；`done` bool **由客户端判定并显式上报**（节点不反推）；`day` string `YYYY-MM-DD`。
- **`position` 归一化（按 type 分派，写死防漂）**：`article` = 正文滚动千分比 `0–1000`；`video` = 已看到秒数；`quiz` = 已作答题数；**`course` / `lesson` 容器不上报**（容器完成度由子条目聚合，只用于展示、不产生事件）。**Go / TS 两份实现与两侧单测都引用本表**。
- **LWW 口径（写死）**：同一 `(id, item_id)` 唯一确定一个寄存器，取值 = `created_at` **降序**、平局取 `event_id` **升序**后的**首条**——与 §7.3 按身份读事件的既有排序逐字一致。
- **打卡日界 = 客户端本地时区**：`day` 由客户端算好写进 `body`，节点**不**用 `created_at` 反推。某日已打卡 ⇔ 存在至少一条 `day == 该日` 的 `progress.v1` 事件；连续天数从「今天（客户端本地时区）」起向前回溯，首个缺口即断（今天未打卡则从昨天起算）。

## 11. 验证方案

- 协议向量对齐：`vectors/` 黄金向量被 Go 与 TS 两侧测试同时消费（canonical 字节、`merkle_root`、Ed25519 签名）。
- Go 单测：canonical JSON、sha256、Merkle、签名验签、pack 导出与读取。
- 身份 E2E：客户端自签身份在**跨节点**验签通过；篡改签名的请求被拒。
- TLS（仅节点↔节点）：未固定指纹 / 证书不匹配的**对端**连接被拒；客户端链路走明文 HTTP，断言公开读接口在明文下仍 200。
- 客户端链路完整性：明文链路上篡改响应体 → 客户端按 manifest / 块哈希拒收（§12.2）。
- ② 类密文断言：节点库与节点块目录中不出现 ② 类明文。
- L4a′ 静态加密断言：直接读取 `data/base.db` 与 `data/blobs/*` 的原始字节，断言不出现 ① 类明文；同时公开读接口仍正常返回明文（透明拆封正确）。
- 恢复 E2E：3 节点，杀 1 个 → 断言补齐与校验（A 阶段）。
- 篡改检测：改动 1 bit → 拒绝加载。
- 真机：Android 断网阅读、下载中断续传、guest 匿名全流程。

## 12. 红线与风险

1. ① 类即全网可复制转存——已接受，不可作为后续抱怨点。
2. 明文视频必然可被翻录——已接受（不做包内加密）。
3. 节点公开读接口等于 ① 类内容完全公开——需重点防护的是**写接口、内部接口、签名私钥、托管私钥密文、L4a′ 静态加密密钥**。
4. 协议双实现是长期负担：任何协议变更必须同时改 Go、TS 与向量三处，缺一即漂移。
5. 节点构建一律开发机交叉编译，服务器只收二进制；禁止要求部署者现场装依赖。
6. 磁盘增长：节点需容量上限 + LRU 淘汰，淘汰前确认别处存在副本。
7. 二期前不做 iOS。
8. 历史 Strapi 用户与积分体系不迁移，账号需重建或另行迁移。
9. **② 类内容不可审**：私信与小组内容节点无密钥，无法先发后审。滥用治理只能靠客户端举报 + 成员自行移出，须在隐私政策写明。
10. **私钥丢失 = 身份丢失**：无任何节点可找回。密码托管只是「换设备取回」的便利；密码遗忘即不可恢复。必须提供密文备份与重装降级路径。
11. **本地库 KEK 为设备随机密钥，不派生自私钥**（2026-09-29 #4 spike 定案，见 §0.4）：`kek_source='device'`，KEK 与密文同库，**不抗 root / 越狱的本地读取**。原「由私钥派生」的表述已作废——私钥自身由 KEK 加密，再由私钥派生 KEK 是死锁。KEK 无备份，私钥丢失连带本地密文不可读；密文级退路见 §8.2。
12. **L4a′ 节点静态加密密钥丢失**：缓存节点可反熵重拉；**权威源节点丢密钥 = 内容不可读**，必须离线保管恢复码（见 §12.1.1）。
13. **节点永不持有组密钥**（2026-09-29 §0.7 补）：不解密 ② 类正文与**圈内决议正文**——封闭圈内容与圈内提案 / 投票正文对节点均为密文；圈内门槛靠**多签验签**（签名者集合 + 签名数）而非节点数票。第 9 条的落地口径。
14. **开放圈不加密**（2026-09-29 §0.7 补）：**开放即公开**，属圈子形态语义，不是加密强度不足；形态**建圈定死、不可切换**（§3、§3.1）。
15. **块保持匿名可取**（2026-09-29 §0.7 补）：`GET /v1/blob/{cid}` **不做逐块鉴权**（会破坏块缓存与 ① 类复用），`cid` 只出现在圈内索引里、对非成员不可达 ⇒ **等价隔离**。这是明确记录在案的取舍。

### 12.1 加密分层与成本结论（2026-09-26 确认）

| 层 | 对象 | 方案 | 结论 |
|---|---|---|---|
| L1 传输 | 节点↔节点 | TLS + 双向 mTLS + 指纹固定 | **做** |
| L2 端到端 | ② 类私信 / 小组正文 | 客户端加密，节点只持密文 | **做** |
| L3 手机本地库 | `plus.sqlite` | **应用层列级加密**（库级加密不可达，2026-09-29 定案，见 §0.4 / §8.2） | **做**（敏感字段；①类保持明文） |
| L4a 节点磁盘静态（文件系统级） | ①② 类内容落盘 | LUKS / BitLocker / 云盘加密 | **做**，零代码，成本在部署文档 |
| L4a′ 节点磁盘静态（应用层） | ①② 类内容落盘（`data/blobs/*` + `base.db` 正文列） | store 层透明 AEAD 封装，单节点自持密钥 | **做**，见 §12.1.1 |

明确不做：

- **L4b 应用层每块加密 + 全网共享内容密钥**：收益接近 0——节点进程必须能解密才能对匿名提供明文下载，持机者本就能读到明文；且一个密钥泄露即全网内容泄露。（L4a′ 不等于 L4b：L4a′ 每节点独立密钥、跨节点仍传明文，见 §12.1.1。）
- **L4c 应用层每块加密 + 每节点独立密钥**：跨节点必须「解密 → 重加密」，反熵 / 秒传 / 副本复制的零成本优势丧失，scrub 开销翻倍；仍不防运维者。性价比最低。
- **① 类公开内容做 E2E 加密**：与「匿名开放、无 token 可拉 `catalog` / `pack` / `blob`」直接矛盾，需改写 P0 验收口径，不采纳。
- **客户端↔节点 TLS（退路 F1，2026-09-26 定案）**：客户端走明文 HTTP。① 类内容本就匿名公开，TLS 的机密性无收益；完整性/认证由签名头（§7.3）与 manifest 验签（§6.4）承担。代价与边界见 §12.2。

**不可达边界（写明以免反复讨论）**：只要节点必须对外提供 ① 类明文下载，「防节点运维者读取 ① 类内容」在技术上不可达。L4a 防的是「物理介质 / 云主机快照被拿走」。

真实的加密成本不在 CPU（AES-NI 下磁盘级与 AES-GCM 都可忽略），而在三处：密钥的生成 / 注入 / 轮换 / 丢失（丢密钥 = 全库不可读）、跨节点语义被打破（L4c 使密文不可直传）、每多一个密钥就多一个运维故障点。L4a 的代价仅落在部署文档（装机步骤 + 恢复密钥流程），是本约束下的最优解。

### 12.1.1 L4a′ 应用层节点静态加密（2026-09-26 追加确认）

**触发威胁**：备份脚本、对象存储同步、误拷 `data/` 目录导致明文外泄。L4a（文件系统级）**防不住这类威胁**——它依赖装机时的系统配置，而备份、同步、目录拷贝都在其之上。

**算法与粒度**：

- AES-256-GCM；封装格式统一为 `nonce(12B) || ciphertext || tag(16B)`，TS 与 Go 两侧由 `vectors/v1/aead.json` 逐字节锁死。
- `data/blobs/<h0..1>/<h2..3>/<blob_id>`：逐文件加密封装，随机 nonce 前置存放。
- `data/base.db` 正文列：本期只加密 `articles.body_md`（值以 `enc:v1:` 前缀 + base64 存，便于识别历史明文行）；`segments` / `quizzes` 本期只有 DDL、无读写路径，A 阶段（课程体系）引入写入路径时同步接入同一套 `encText` / `decText` 并补验收。

**落点（唯一改动位置）**：`internal/store` 一层做透明加解密——写时封装、读时拆封。`internal/httpapi` / `internal/packexport` / `internal/sync` **零改动**。属 P0 已实现代码的复用改造，**不删除**。

**密钥**：

- **独立密钥，不派生自签名私钥**（解耦：签名私钥丢失不应连带全库不可读）。
- 来源（四级优先级）：代码/测试注入 `WithStoreKey` → `BASE_STORE_KEY`（env，hex64）→ `BASE_STORE_KEY_FILE`（文件路径）→ 默认文件 **`data.key`**（`data` 目录的兄弟文件，0600），末者不存在则**首启自动生成**。
- **密钥文件必须在 `data` 目录之外**：`cp -r data` / 只备份 `data` 不应连密钥一起拷走。**残余风险**：备份**整个安装目录**仍可解密——只有把密钥经 env 注入（`BASE_STORE_KEY` / `BASE_STORE_KEY_FILE`）且不入镜像才能根除。
- 启动日志只回显密钥前 8 个 hex；完整密钥用 `based store-key show -data <dir>` 按需取（把完整 hex 写进日志等于留在日志文件与运维平台上）。
- 丢失后果：缓存节点可反熵重拉；**权威源节点 = 内容不可读**，只能靠恢复码。

**硬约束**：

- `blob_id` **在明文上计算**，加密只改磁盘表示 → 去重 / 秒传 / 副本因子 / 反熵 / Merkle 全部不变（§3.2）。
- 跨节点仍传**明文** + TLS → **零重加密**。这是 L4a′ 与 L4c 的分界线：一旦要求跨节点也传密文，就退回 L4c 的「解密 → 重加密」，本方案作废。

**明确不加密**：`data/packs/`（可重导产物）、② 类密文（E2E 后已不可读）。对二者加密只增算力开销与故障点，无收益。

**已知代价**：

- 正文列加密后不可 SQL 检索 / LIKE（P0 无全文检索需求，影响可接受）。
- 每多一个密钥多一个运维故障点。
- 无新增第三方依赖（Go 标准库 `crypto/aes` + `crypto/cipher`）。

**不可达边界不变**：仍不防有 root 的节点运维者——节点进程必须能解密才能匿名供读 ① 类明文。

### 12.2 TLS 信任模型（2026-09-26 重写：两条链路分开定）

| 链路 | 方案 | 理由 |
|---|---|---|
| **节点↔节点** | **双向 mTLS + 证书指纹固定（白名单）** | 节点间要传签名内容包与明文块，必须防中间人替换；节点数量少、指纹经人配对，运维成本可接受 |
| **客户端↔节点** | **明文 HTTP**（退路 F1） | ① 类内容本就匿名全网公开（§3 铁律 2），TLS 的机密性无收益；留下的「完整性 + 认证」由签名头（§7.3）与 manifest 验签（§6.4）承担；自签证书在 Android 上要么装根证书、要么客户端做 pinning，成本不划算 |

**F1 的代价（写明以免反复讨论）：**

- 明文链路上的**被动旁观者**可读到 ① 类明文内容与请求路径；**写请求的正文同样可读**——签名头保护的是「谁发的、有没有被改」，**不是「内容不给谁看」**。
- 主动拦截者可**阻断**请求（可用性不保），但**不能伪造内容**（manifest 与块均按哈希验真）、**不能冒用身份**（验签失败即拒）。
- ② 类密文与私信 / 小组正文在客户端已加密 → 明文链路上仍不可读。
- 「内容不被旁观者拿到」的诉求不在本系统范围：① 类的定位就是全网可复制（§3 铁律 2）。

**节点自身身份不因客户端明文而消失：**`-tls-cert=off` 只表示「主监听不加密」；只要启用了对端监听，节点仍从默认路径 `data/tls/node.crt|key` 生成/加载双向 mTLS 所需证书。

- **状态**：2026-09-26 已确认，不再拟定；已在生产双节点真机验证（主节点 TLS :443 + 缓存节点明文 :80，两侧反熵收敛、对端 :8082 mTLS 拒绝非白名单客户端、缓存节点证书指纹不变）。

- 彻底脱离 Strapi：base 完全独立，basic 仓库与 16 个 `zhao-*` 插件全部退出本项目。

- **可见性（2026-09-26 新增）**：三类——① 公开可分发（明文 / 匿名 / 可复制）、② 加密可分发（密文 / 可复制不可读）、③ 受控内容（不进本系统）。
- **加密范围（2026-09-26 确认，追加 L4a′）**：L1 + L2 + L3 + L4a（文件系统级）+ **L4a′（应用层节点静态加密，§12.1.1）**；L4b / L4c / ① 类 E2E 不做（§12.1）。
- **存量（2026-09-26 新增）**：P0 已实现全部保留，复用或闲置，**不删除**。
- 第一条纵切：**身份 + TLS + 节点静态加密（L4a′）**（不做任何互动形态）。
- 节点职责：收敛为 **id 登记 + 版本对齐**；内容分发是可替代的缓存职能。
- 节点形态：**单进程自包含**（内容库 + 公开读 + 同步 + 身份登记 + 浏览页同一进程）。
- 节点运行时：**Go 静态单文件**（纯 Go SQLite，无 CGO），本地电脑与服务器同构部署。
