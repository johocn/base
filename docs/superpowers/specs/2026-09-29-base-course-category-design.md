## 0. 改版说明

### 0.1 2026-09-29 初版

**动机**：总纲 §6.0 的课程体系原为 `course → lesson → (article | video | quiz)` 三级，**没有分类概念**——手机端首页只是「课程 / 未归类」两组的平铺列表。学习站点需要「课程分类管理」这一层组织能力，同时用户明确要求「课程、课时、文章可以关联答题系统，测试学习情况」。

**本册第一次定义（新增）：**

- **分类容器条目** `category/<slug>`：`source=category` / `type=category` / `sqlite_table=segments`（总纲 §0.8 已回填 §6.0 取值集合）
- **单归属·单级扁平** 的归属模型：一个 `course` 至多属一个分类；归属由**分类侧单向清单**表达，`course/<cid>` 的 `item_id` **一律不动**（§3）
- **导入器 front-matter 三个新键** `category` / `category_title` / `category_digest`，以及「一课程出现在两个分类即报错」的单归属校验（§3.4）
- **手机端四级浏览**：分类 → 课程 → 课时 → 载体，另设「未归类」组（§5）
- **答题关联的入口口径**：不改任何契约，只规定「哪一个 quiz 属于哪一层」与三个入口（§4）

**明确沿用、不改动：**

- 内容包规范 v1：`manifest.json` 的字段名与类型、`pack.sqlite` 五表 DDL 与列顺序；**不新增表、不新增字段、不 bump `schema_version`**
- #14 §3.1 的 `segments` 行语义（`seq=0` 简介、`seq>=1` 子项清单）与 §3.3 的**两条哈希口径**（行级 / 条目级）——新容器直接复用，确定性导出性质不变
- #14 的 `store.UpsertSegmentItem` / `ListSegments` / `ImportPack` 的 `segments` 分支、`packexport` 的 `exportableTables` 白名单（已含 `segments`）——**分类条目全部复用，节点侧零新代码**
- #14 §2.2 的旧 id 墓碑退役口径、§5.3 的手机端旧数据启发式平移
- `dist_class` 这一唯一的可见性维度：分类条目一律 `public`

### 0.2 2026-09-29 执行期口径回填

实施计划（`plans/2026-09-29-base-course-category-plan.md`）执行期发现本册四处口径未定义或与既有实现冲突，按「先改文档」次序就地回填：

1. **§3.1 补「分类内清单顺序」**：分类没有 `order` 键，清单按 `course/<cid>` 的 **cid 字典序升序** 排列。这是 §3.3 确定性导出的必要条件（同一输入重复导出字节一致），不得依赖文件遍历顺序。
2. **§3.2 补「未被本轮声明的既有分类」**：导入器对**库中既有**的每个 `category/*` 条目也做一次重算；本轮未声明课程的分类被重写成**无课程行**的容器（`title` / `digest` 沿用既有），客户端跳过空清单分类，故不出现空分组。不计入重算会让 AC 3（归属可换且旧分类清空）直接失败。
3. **§3.4 补两条 fail-fast**：`category` 非空时必须是合法 slug（沿用 #25 §2.4 的 `[a-z0-9][a-z0-9-]{0,63}`，判定落在 `protocol.ValidSlug`）；声明了 `category` 就必须有 `course`（分类只承载课程归属）。两者与单归属校验同在**任何写库之前**发生，失败时 `Run` 返回 `(Result{}, err)`，库里零改动、不产出任何包。
4. **§6 AC 7 措辞收窄**：原文「节点与本地均无任何作答结果行」不成立——本地 `quiz_attempt` 表与 `pages/quiz/quiz.vue` 结算时的 `addAttempt` 是 #8 范围的**既有**行为，本册不动、不删、不改。AC 7 判据改为「**本册不新增任何作答结果写入**；节点侧无作答结果表；分类与答题入口的改动不触及 `quiz_attempt`」。§4「不记录任何作答结果」一句同步加限定词「不**新增**」（已就地改）。

## 1. 目标与判定

| # | 目标 | 判定 |
|---|---|---|
| 1 | 课程有分类这一层组织 | 导入器按 front-matter 产出 `category/<slug>` 条目，手机端首页按分类分组（§3、AC 1） |

## 3. 契约

### 3.1 分类条目形态

| 项 | 值 |
|---|---|
| `item_id` | `category/<slug>` |
| `source` / `type` | `category` / `category` |
| `sqlite_table` | `segments` |
| `dist_class` | `public`（分类是 ① 类组织信息，不含权限） |
| `segments` | `seq=0` 分类简介（行语义按 #14 §3.1 既有口径）；`seq>=1` 该分类下的 `course/<cid>` 清单，**`kind` 只允许 `course`** |
| `title` | 分类显示名，来自 front-matter `category_title`（缺省回落为 `slug`） |

- `slug` 规则沿用 #25 §2.4：`[a-z0-9][a-z0-9-]{0,63}`。
- 分类条目**只承载「简介 + 课程清单」两类行**，不得承载正文、题组或任何其它内容。
- 分类之间**无上级容器**，因此**不引入排序字段**：手机端按 `item_id` **升序**（`category/<slug>` 的字典序）渲染，稳定且确定。

### 3.2 归属模型：单归属 · 分类侧单向清单

归属由**分类条目的清单**表达，而不是由课程声明自己的分类：

```
category/<slug>
  ├─ segments seq=0  kind=digest  text=<分类简介>
  └─ segments seq>=1 kind=course  text=course/<cid>
```

由此三条性质（**本册最硬的三条**）：

1. **`course/<cid>` 的条目与 `item_id` 一律不动**——加分类、换分类、去分类都只改分类条目的清单，课程的 `content_hash` 不变，块级影响为零（复用 #14 §3.2 的推论）。
2. **一个课程至多属一个分类**：判定 = 在所有 `category/*` 条目的清单里扫描该 `course/<cid>`，出现的次数必须 ≤ 1。这是**导入器侧的硬校验**（§3.4），节点侧不做实时判定。
3. **课程归属由扫描派生**：手机端与节点公开读都不需要「课程 → 分类」的额外索引——扫一遍分类清单即可（分类数量级远小于课程）。

**悬空引用**（清单里有 `course/<cid>` 但该条目不存在）：客户端**静默跳过**，不显示、不报错（与「未归类」并存，不是错误状态）。

### 3.3 哈希口径（一字不改，仅申明适用）

分类条目**直接复用** #14 §3.3 的两条口径：

| 层级 | 口径 |
|---|---|
| 行级 `segments.content_hash` | `hex(sha256(UTF-8(text)))` |
| 条目级 `items.content_hash` | `hex(sha256(按 seq 升序拼接的 "<kind>\t<text>\n" 的 UTF-8 字节))` |

同一份输入重复导出必须字节一致；实现直接走既有 `SegmentsContentHash`，**不新造规则**。

### 3.4 导入器：front-matter 三键与单归属校验

在 #14 §4.2 已有的 `course` / `course_title` / `course_digest` / `lesson` / `lesson_title` / `order` 之外，新增**文档级**三键：

| 键 | 必填 | 说明 |
|---|---|---|
| `category` | 否 | 分类 `slug`；**缺省即该课程进「未归类」** |
| `category_title` | 否 | 分类显示名；缺省回落 `slug` |
| `category_digest` | 否 | 分类简介 |

**单归属校验（fail fast）**：分组阶段按 `(category, course)` 聚合后，若同一 `course` 出现在两个不同 `category` 下，**导入器立即报错并退出，不产出任何包**。理由：静默取其一会让「哪一份声明生效」取决于文件遍历顺序，产生不可复现的导出结果。

**同课程跨文档一致性**：同一 `course` 的多份文档若 `category` 声明不一致，同样命中上面的报错（它们就是「一课程出现在两个分类」）。

### 3.5 与既有包的互通

- **新包进旧客户端**：`category` 是未知 `source`，旧客户端按既有「未归类」逻辑处理——分类条目被忽略、课程正常显示（不会崩、不会丢内容）。
- **旧包进新客户端**：不含任何 `category/*` 条目 ⇒ 全部课程进「未归类」（与 AC 6 同一条）。
- **不要求重新导入**：既有包与新包可并存；分类化是一次纯增量操作。

## 4. 答题关联（零契约变更）

**「关联」不是一个新机制，而是既有的归属链路**：quiz 本来就以载体形态挂在课时下（`course/<cid>/lesson/<lid>/quiz/<qid>`），或作为不属于任何课程的独立题库（`quiz/<qid>`，#25）。本册只规定**入口**：

| 入口 | 呈现的测验 |
|---|---|
| 课程页 | 该课程全部课时内的 quiz，**按课时顺序分组** |
| 课时页 | 该课时内的 quiz |
| 文章页 | **该文章所属课时内**的 quiz（文章与 quiz 是同一课时的姊妹载体）；文章无课程归属时无此入口 |

**明确不做：**

- **不新增任何作答结果写入**：得分、尝试次数、错题本一律归 #8（学习进度与打卡），本册**不落任何学习态字段**；本地 `quiz_attempt` 表与 `pages/quiz/quiz.vue` 结算时的 `addAttempt` 是 #8 范围的既有行为，本册不动、不删、不改（§0.2 第 4 条）。
- **不引入关联表、不引入 `quizzes` 新列**：关联完全由 `item_id` 前缀表达。
- **不引入「跨课程的题库关联」**：一个 quiz 只属于它的课时或独立形态，不做多对多。

## 5. 手机端设计

### 5.1 数据面

| 位置 | 改动 |
|---|---|
| `LocalRepo` / 本地表 | **零新表**：分类条目落在既有 `items` + `segments`（`items.source` 是 TEXT，无枚举约束） |

### 5.2 四级浏览

```
分类（category/<slug>，按 item_id 升序）
  └─ 课程（course/<cid>，按分类清单 seq 升序）
       └─ 课时（course/<cid>/lesson/<lid>，按 seq 升序）
            └─ 载体（article / video / quiz，按 seq 升序）
未归类
  ├─ 未分类课程（无任何 category 清单引用的 course/<cid>，按 item_id 升序）
  └─ 独立内容（article/<aid> 与 quiz/<qid>，按 item_id 升序）
```

| 项 | 内容 |
|---|---|
| 页面 | `pages/course/course.vue` 由「课程 / 未归类」两组改为「分类分组 + 未归类」；分类点击进课程列表（可复用同页或新增一层），课程以下三级**沿用 #14 既有页面与路由** |
| 空态 | 全站无任何分类时，首页**退化为两级**（课程列表 + 未归类），不显示空的「分类」层——与旧版视觉一致 |
| 不受影响 | 「未归类」的判定口径与既有实现一致（无课程归属），只是课程侧多了一层归属来源（分类清单） |

## 6. 验收（AC）

| AC | 内容 | 判定方式 |
|---|---|---|
| 1 | 分类端到端 | 带 `category` 的 front-matter 导入 → 导出 → 另一节点导入 → 分类条目与其课程清单可读且一致（§3.1、§3.4） |
| 2 | 单归属 | 同一 `course` 声明两个 `category` → 导入器报错退出、**不产出任何包**（§3.4） |
| 3 | 归属可换 | 同一批文档改 `category` 后重新导入 → 课程在新分类下、旧分类清单里不再出现，**课程 `content_hash` 不变**（§3.2） |
| 4 | item_id 不动 | 分类化前后，全部 `course/<cid>` 与 `lesson` / 载体条目的 `item_id` 逐字一致（§3.2） |
| 5 | 确定性导出 | 同一输入重复导出，`pack.sqlite` 字节一致、分类条目 `content_hash` 不变（§3.3） |
| 6 | 老包兼容 | 不含 `category` 条目的包导入 → 全部课程进「未归类」，无报错（§3.5） |
| 7 | 答题入口 | 课程页 / 课时页 / 文章页均能进入应测 quiz；**本册不新增任何作答结果写入**，节点侧无作答结果表，分类与答题入口的改动不触及 `quiz_attempt`（§4、§0.2 第 4 条） |
| 8 | 悬空引用 | 手工构造「清单指向不存在的课程」的包 → 客户端跳过该项、不崩、不影响其它课程（§3.2） |
| 9 | 门禁全绿 | `go build ./...` / `go vet ./...` / `go test ./...` 全包 ok；mobile vitest 全绿；`tsc --noEmit` 干净；`build:h5` / `build:app` 通过；两条发布前检查无输出（同 #9 §0.2「更正 14」） |

## 7. 风险与红线

### 7.1 残余风险（照实写）

| # | 风险 | 现状与处置 |
|---|---|---|
| 1 | **分类只有一层**，深度需求出现时无法表达 | 刻意的边界（§1）；要树形需另立册子，届时须先改总纲 §6.0 |
| 2 | **分类归属由导入器单点决定**，节点侧无管理接口 | 分类调整是运营动作（重新导入），与「课程编排归导入器」同一口径；节点不留旁路 |
| 3 | **单归属校验只在导入器**，节点导入一个「被手工改坏」的包时不复检 | 接收侧只按既有 `ImportPack` 入库，悬空/重复由客户端与 AC 8 兜住；不新增节点侧校验（避免与运营路径分叉） |
| 4 | 「未归类」组可能随分类调整频繁变动 | 客户端按 `item_id` 升序渲染，结果稳定可复现 |

### 7.2 红线

1. **分类不表达权限**：可见性仍只有 `dist_class` 一维，分类是纯组织信息。
2. **不得改写任何既有 `item_id`**：分类只增条目与清单行，不重命名、不复用旧 id（§3.2）。
3. **`category/<slug>` 只由导入器产出**：`POST /v1/submit` 明确拒绝该前缀（#25 §2.4 已登记），节点不新开写接口。
4. **分类条目不得承载内容**：导入器只产出 `kind=digest`（`seq=0`）与 `kind=course`（`seq>=1`）两类行；接收侧不新增校验（见 §7.1 风险 3），客户端遇其它 `kind` 静默跳过。
5. **不落任何学习态字段**：作答结果、进度、打卡一律归 #8（§4）。

## 8. 明确不做

分类多级树；课程多归属；节点侧分类管理接口（增删改分类一律走导入器）；节点公开浏览页（`/`）的分类分组（它是浏览页，不是学习入口，保持现状）；**作答结果记录**（归 #8）；视频播放器；跨课程题库关联；`tags_json` 的任何使用（归 #37）；内容包规范 v1 的任何变更。
