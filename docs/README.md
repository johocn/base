# base 文档地图

本文件是全部设计文档的**索引与边界登记**。任何新增文档必须先在此登记「职责 / 明确不做什么 / 依赖 / 状态」，否则视为孤儿文档。

## 1. 文档分层

| 层 | 路径 | 作用 | 是否可含实现细节 |
|---|---|---|---|
| 总纲 | `docs/superpowers/specs/*-base-distributed-learning-design.md` | 全局铁律、可见性模型、内容包规范、分期 | 否 |
| 册子 | `docs/superpowers/specs/YYYY-MM-DD-base-<topic>-design.md` | 单一主题的完整设计（一条主线或一条纵切） | 接口级可以，代码级不可以 |
| 计划 | `docs/superpowers/plans/YYYY-MM-DD-base-<topic>-plan.md` | 由册子派生的可执行任务清单 | 是 |
| 代码 | 仓库源码 | 唯一实现 | — |

## 2. 硬规则

1. **总纲是唯一上游**。册子与总纲冲突时，先改总纲（走「## 0. 改版说明」）再改册子，禁止只改册子。
2. **一份册子只覆盖一条主线或一条纵切**，不做「大而全」。
3. **每份册子通过评审后，各出一份独立计划**；一份计划只覆盖一个阶段。
4. **架构约束只写在文档里**，通过目录与包结构隐性落地，不写进生产代码注释，不做自定义抽象。
5. **重大改版不用新文件**：在文档顶部 `## 0. 改版说明` 追加一节，写清作废什么、新增什么、保留什么。
6. 文档不承载秘密：不写真实私钥、真实密码、生产密钥指纹。
